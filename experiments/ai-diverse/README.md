# 多类型 AI 离线训练实验

本实验按“先扩大训练数据，性能合格后再接入比较”执行。基线来自 `test/ai-2.1` 的 `cb2fd451bc234c2a6904c8a91f85454d0375de35`。本实验提交仅新增实验脚本、候选权重与汇总报告；`src/`、`native/`、默认模型、版本号、Pages 与发布流程均不修改。本目录中的候选不自动装载进产品。

## 暂存的缓存想法

A1–A8 均只记录，不在本轮实现：Worker 提前返回完整结果；静态目录预编码与有效条件摘要；同 Worker 的小型已验证查询内存缓存；每次命中检查最新持久缓存元数据；减少深拷贝；静态目录按变化初始化；小结果直接传输与大结果确认分块；轻量持久化精确最终结果。2.1 已有功能保持原样。

## 数据来源与范围

使用仓库冻结的公开 CN/JP 目录及可重现的合成库存、规则条件，不使用私人账号抓取。目录内容 SHA-256、种子范围、每类统计、压缩文件校验和见 `reports/dataset.json`。生成 12,000 个训练条件、2,400 个调参验证条件、2,400 个封存测试条件，每个拆分在 24 类中均匀分配。

| 类别 | 覆盖内容 |
| --- | --- |
| synthetic | 随机小库存及基础组合 |
| cn-small / jp-small | 公开目录中 6–16 个从者的小库存 |
| cn-medium / jp-medium | 30、60、120 个从者 |
| cn-large / jp-large | 120、240 个从者 |
| cn-full / jp-full | 当前冻结目录全量可用从者 |
| tight-cost | 0–30 等紧 COST 条件与不可行样本 |
| mixed-stock | 重复持有、非满破/满破、缺失礼装 |
| forms | 灵基形态、形态 COST 和特性变化 |
| event-self / event-party | 自身与全队活动加成 |
| bond15-aura | 满羁绊状态及全队光环 |
| pins-empty | 必选、前后排、固定位置和空位 |
| no-support-six-own | 无助战、不同最低自有成员数 |
| rounding-flat | 舍入边界、零基础值、固定 +50 |
| trait-overlap | 多种特性礼装覆盖重叠 |
| inventory-changes | 已满羁绊与礼装持有状态变化 |
| general-normal | 通用精确搜索，锁定与空位 |
| general-grand | 冠位规则及位置变化 |
| general-target-bonus | 指定目标的活动加成 |
| general-system-npc | 必选系统助战规则 |

这些是有限的规则组合，不代表覆盖所有关卡、未来规则或真实用户分布。大库存样本主要仍是 3–7 种礼装目录、每种 1–3 份，并非礼装数量无上限的压力测试。通用搜索目前限于合成的 5–8 从者。当前 16 维特征也没有表达全部规则关系；扩充数据不能消除特征表达上的限制。

## 标签与隔离

教师为同一精确求解器关闭 AI 的结果，保留原有精确约束和最优性检查。库存教师与原生 2.0.0 独立工作树交叉核验；通用教师是在临时复制模块中插入仅观察候选域的钩子，并与未插桩的求解器核验。每个拆分前 240 个条件执行交叉核验，覆盖每类 10 个条件。不得据此宣称全部样本经独立算法证明。

不可行条件只保存状态，不生成选择标签；超时和异常也不作为最优答案训练。标签是一个精确最优解的选择，不是“所有可接受解”的集合。对于同一查询中完全相同的从者特征，将等价特征的正例合并，避免学习任意身份的择一结果。礼装目标为效果组的选中数量 / 可选容量。每个查询的样本权重归一，防止全目录查询按候选数淹没小库存。

训练、验证、测试使用独立种子。训练程序只读取训练和验证标签；测试文件可作压缩完整性、索引和跨拆分条件去重检查，但不参与参数更新、选模或验证阶段的质量/耗时测量。验证不达标时不启用测试评估。

## 模型与验收

保持 featureVersion=1 的 16 维输入，分别训练隐层为 16、32、64 的双头 tanh MLP。NumPy Adam、固定种子、查询平衡 soft BCE；输入标准化后折叠进导出权重，兼容现有只读推理接口。按验证损失选出排序候选，再离线测量精确求解收益。候选通过 `aiModel` 显式注入测试调用，不替换默认权重。

离线耗时包含模型推理、候选核实和完整精确搜索；关闭查询结果缓存，按条件交替 AI 开/关顺序，每个条件重复 3 次，比较每个条件的中位数。通用搜索使用原模块，计时不包含标签观察钩子。此步骤是候选资格检查，不是 2.0.0 / 2.0.9 / 2.1 的产品接入对比，也不代表端到端设备表现。

本轮预设的保守工程门槛（尚非用户指定的 SLA）：所有条件精确分数及 COST 一致、无未完成项；可行条件累计中位耗时至少下降 10%，bootstrap 95% 区间上界小于 1；启用 AI 的库存查询中可行候选率至少 95%、候选已达到最终最优分数的比例至少 60%；各类 P95 无超过 5% 的退步。240 个耗时条件每类约 10 个，因此各类尾延迟仅作为初筛，不能当作稳定设备性能结论。即使通过，也需封存测试与后续更大样本设备验收后才考虑接入。

候选只提供排序/有限候选建议；精确求解仍负责可行性、评分、约束与最优答案。模型预测不能充当剪枝界限或直接返回答案。

## 重现

```sh
# 当前实验支线，在相邻路径取原始 2.0.0 教师作独立核验。
git worktree add --detach ../teacher-200 native-v2.0.0
FGO_AI_TEACHER_BASELINE="$(realpath ../teacher-200)" node scripts/build-ai-diverse-data.mjs
OPENBLAS_NUM_THREADS=2 OMP_NUM_THREADS=2 python3 scripts/train-ai-diverse.py
python3 scripts/verify-ai-diverse-data.py
node scripts/evaluate-ai-diverse.mjs
# 可显式指定另外两个候选，报告按隐层容量分别保存。
FGO_EVAL_MODEL=experiments/ai-diverse/models/candidate-16.json node scripts/evaluate-ai-diverse.mjs
FGO_EVAL_MODEL=experiments/ai-diverse/models/candidate-64.json node scripts/evaluate-ai-diverse.mjs
```

Python 3.12 / NumPy 2.3.5，Node 24。脚本在压缩流完整结束后解压复核条数、唯一索引，再原子改名并记录 SHA；训练时重新校验 SHA 和条数。`FGO_TRAIN_EPOCHS` 可调整训练上限，默认 120，按验证损失提前停止。各脚本的环境变量可缩小试运行规模，但正式报告必须注明实际数量。

封存测试命令仅在验证门槛通过后使用：

```sh
FGO_EVAL_SPLIT=test FGO_OPEN_SEALED_TEST=1 node scripts/evaluate-ai-diverse.mjs
```

具体模型、损失、耗时与是否通过，以 `reports/` 内的机器可读结果和 `RESULTS.md` 为准。未通过时继续保留离线候选，产品接入与三版本比较继续暂缓。

训练、验证、封存标签及逐次测量文件不上传。仓库仅保留模型、生成与训练程序、汇总报告和校验摘要。新会话从本目录的 `REPRODUCE.md` 开始，可用固定种子重新生成。历史文件 SHA 仅用于核对本轮产物；并行完成顺序、计时和超时会影响重跑文件字节，不保证重新生成相同压缩文件摘要。
