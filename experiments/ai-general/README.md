## 模型与求解器的职责

网络只预测五种完整搜索策略的工作量，选择搜索顺序与是否启用确定性的最低成员 COST 预留检查。它不预测最优分数，不产生可采信的上下界，不删除某个合法数量或候选。完整求解仍由原库存精确求解器的身份、形态、站位、礼装库存和 COST 规则完成，不设置搜索时长上限。

五种标签策略为：原顺序；效果/COST 优先；低 COST 效果组优先；数量从零递增；覆盖率排序配合居中数量顺序。后四种都使用确定性 COST 预留：对每个身份取最便宜形态，先计必选身份，再补足至少需要的身份数。这是忽略部分约束得到的必要条件下界，不能把模型预测当作下界。增加更强的安全剪枝应单独证明并重新验收。

`general-ai-solver.mjs` 在启动时读取原求解器，通过受保护的源码标记生成两个研究副本（计时版及工作量统计版）。只在初始化期间写入并立即删除两个小型模块文件；普通查询不写文件。生产集成应改成显式接口，不能直接把这个研究加载器放进浏览器。

输入为 35 维聚合特征，涵盖效果组、特性向量、身份/形态数、COST/库存分布、效果覆盖与重叠、满羁绊/光环、自体加成、必选、前后排/固定位置/空位、助战布局与固定加成。没有从者或礼装 ID、名称的可训练嵌入。网络为 `35 → H(tanh) → 5`，H 候选 8/16/32，导出 JSON，标准化折叠进首层。

教师对每个条件完整运行五种策略，标签为 `log(1 + DP 转移尝试数 + 上界行访问数 + 搜索节点数)`。内部实际回归基线 log 工作量及四种相对差值，导出时折叠为五个绝对预测。该计数只是工作量代理，不含所有 CPU 指令、神经推理、预留表构造等开销；实际提速必须看完整求解计时。

训练仅访问训练集：按索引模 7 划分内部拟合/容量选择，不能称为外部验证。Adam，batch 512，学习率 0.002 每轮 ×0.99，β=(0.9,0.999)、ε=1e-8，L2=0.0001，梯度裁剪 [-5,5]，最多 160 epoch，内部损失连续 20 轮无 1e-5 改进停止。种子 99600+H；基线输出损失权重 0.08，其余 1；存在至少 15% 工作量改善的训练条件加权 2。实际模型、摘要与轮数见 `reports/training.json`。

## 结构隔离与适用范围

| 集合 | 规则组合 | 成员数 | 礼装目录组数 | 特性结构 |
|---|---|---:|---:|---|
| 训练 | 无规则、单规则及六种双规则 | 5–12 | 2–5 | 随机关联 |
| 校准 | 三种独立三规则组合 | 7–15 | 3–6 | 循环关联 |
| 验证 | 另外四种三规则组合 | 8–24 | 4–7 | 分块/循环关联 |
| 封存测试 | 四种四规则组合 | 12–36 | 5–8 | 嵌套关联 |

规则原子为特性、满羁绊光环、自体加成、形态、位置约束、固定加成。集合的规则组合完全分离；数值取值、主要 COST 集合、特性生成方式也分离。预算类别仍共享，基本数学算子共享，这不表示所有条件维度都完全不同。具体家族与种子固定在 `general-ai-cases.mjs`。目录组不等于最终合并后的效果组数，正常/满破可产生更多组。

ID 采用各集合分离的合成空间。ID 与排序无关的语义指纹保留身份与多个形态的归属、真实效果关联、库存和限制；近重复指纹进一步量化数值、去除基础羁绊。所有集合两两检查精确、近重复与规则组合交集。指纹不是对任意图同构完美的数学判定，报告只说明这些已实现检查通过。

当前只覆盖库存求解器的上述规则子域：全队活动加成未随机化；冠位、系统 NPC、通用特殊锁定、指定目标活动等完整通用路径没有接入。本模型可以处理既有算子组成的新礼装和新数值；如果引入新算子、条件语义或更大规模，需要兼容性检查和新验收，不能承诺覆盖未来所有规则。

## 条件启用与验收

先用原始持有礼装数量做低成本筛选，再在精确求解器完成效果分组后判断组数。满足时才提取特征和推理；模型版本、形状或特征不兼容时回到原精确路径。校准只选择启用门槛，不修改模型；冻结后才运行外部验证。封存测试要求同一模型的验证资格通过，并显式设置开封变量。

如果校准没有选出满足净收益门槛、并在总时间与 bootstrap 上胜过无 AI 确定性下界对照的启用条件，gate 保持关闭，停止性能资格流程；不运行一个全程关闭 AI 的验证并冒充模型验证通过。若外部验证或测试失败，保留冻结的校准 gate 供复现，交付 gate 改回关闭。

完整计时包含求解器准备、特征提取、推理、排序、COST 预留、完整搜索和结果构造；各变体轮换顺序，每查询三轮取中位数。无逐候选磁盘日志。离线基准每查询只保存一条有界记录，和训练样本一起放在不上传的 `data/`，这不属于用户查询路径。

比较原求解器、AI 条件路由、关闭 AI 但始终启用同一个确定性 COST 下界的对照。不能把确定性下界的全部收益归于 AI。门槛检查包含总时间、分家族总时间/P95、查询级 bootstrap、触发数量、精确分数/最低 COST/助战备选一致性、文件写入。研究计时不能替代浏览器、手机与真实账号端到端验证，不能证明逐个输入永不降速。

## 同分组合

`createTieView(opts, verifiedScore)` 保留原始身份、形态、礼装 ID、正常/满破库存与站位域。创建时不枚举，调用迭代器时逐个验证并返回同分合法队伍，因此预算内 COST 更高但同分的组合也不会因最低 COST 代表被删掉。相同库存副本不重复计作物理不同物品。

它是独立的惰性参考枚举器，没有接入软件列表，也没有实现快速随机访问、总数或大规模压缩索引；遍历全部同分队伍仍可能指数级。消费者应按页拉取并允许停止，不应展开成完整数组。调用期间输入应保持稳定。当前自动核验的手算实例数为 12、84、3、96、24、12、36，最后一项覆盖一张较强礼装与两张较弱礼装达到同等最优加成；不据此声称已证明所有真实账号规则下的全组合展示完整性。

## 复现

建议 Node 24、Python 3.12；NumPy 固定版本见 requirements。无需下载训练数据，无需个人账号数据，也无需重新运行 v1/v2 训练。

```sh
git clone --branch research/ai-general-search https://github.com/springs59/FGO-Max-Bond-Team-Setup.git fgo-training
cd fgo-training
git rev-parse HEAD
python3 -m venv .venv
.venv/bin/python -m pip install -r experiments/ai-general/requirements.txt
npm ci
FGO_GENERAL_TRAIN=30000 FGO_GENERAL_WORKERS=4 node scripts/build-general-ai-data.mjs
OPENBLAS_NUM_THREADS=2 OMP_NUM_THREADS=2 .venv/bin/python scripts/train-general-ai.py
node scripts/general-ai.test.mjs
FGO_GENERAL_SPLIT=calibration FGO_GENERAL_N=1500 node scripts/benchmark-general-ai.mjs
node scripts/audit-general-ai-splits.mjs
node scripts/calibrate-general-ai.mjs
# 仅在校准 gate.enabled=true 时，冻结模型与 gate 后运行外部验证。
# 样本数以 RESULTS.md 的实际记录为准。保存 gate-calibration-frozen.json 供复现。
FGO_GENERAL_SPLIT=validation FGO_GENERAL_N=1000 node scripts/benchmark-general-ai.mjs
node scripts/audit-general-ai-splits.mjs
FGO_GENERAL_SPLIT=validation node scripts/qualify-general-ai.mjs
# 仅当匹配模型的验证资格 passed=true 时，才可打开独立测试。
FGO_GENERAL_SPLIT=test FGO_GENERAL_N=1000 FGO_OPEN_GENERAL_TEST=1 node scripts/benchmark-general-ai.mjs
node scripts/audit-general-ai-splits.mjs
FGO_GENERAL_SPLIT=test node scripts/qualify-general-ai.mjs
```

教师默认 4 个 Worker，每个 768 MiB 老生代；基准一个 Worker，1024 MiB 老生代。这些不是整个进程的 RSS 硬上限。教师数据有 80 MiB 文件预算，基准不生成搜索树或候选日志。长任务按 15 秒心跳观察，不用超时判不可行。

计时期间不要并发训练或测试。基准使用独占锁、唯一 runId、每行模型版本与核摘要，最终从有界内存记录一次构造输出，完整条数/唯一索引/摘要检查后才原子发布正式汇总；追加日志只是中途观察及恢复来源。核摘要含本地导入绝对路径，用于单次运行混用检查；跨目录比较使用 Git 提交与源码摘要。会话中断留下的锁不能直接覆盖，先确认原进程已停止并保留中断报告。生成器/教师源码变化时禁止续写旧标签；使用干净数据目录或新路径。字节摘要、权重和耗时可能因完成顺序、平台与数值库而不同。

本轮状态为训练完成、校准失败、AI 关闭，见 RESULTS。补算缺失持久化记录的可选恢复工具只适用于明确的最终日志完整性失败；调用前必须确认失败进程已经退出，并显式设置 `FGO_GENERAL_CONFIRM_FAILED_PROCESS_EXITED=1`。它不会隐藏恢复阶段，不把错误或未完成搜索补记成成功。
