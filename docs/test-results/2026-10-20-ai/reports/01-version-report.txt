 主要发现
 1. 当前高起点版在可比普通矩阵中的条件中位耗时合计为 4.30 秒；框架版为 4.55 秒，合计减少 5.4%。

 2. 按每个条件等权的耗时比几何平均，当前版 / 框架版为 1.021。这与合计耗时的加权方式不同，不能据单个总数断言所有查
 询都更快。

 3. 普通条件完整可比 38/38；跨版本输出差异 0 个条件，独立可行性/结算失败 0 个条件。压力矩阵完整完成 1/4 个条件。

 4. 当前版在适用路径中仍最多调用一次模型。可比核心样本中的起点平均为最终最优收益的 99.8%，达到至少 95% 的为
 21/21。起点高不代表必然提速，构造与核实也占时间。


 报告范围
 这是同一 Linux / Node 环境下的计算源码与生产 Worker 入口对照，不是 Windows EXE、Android APK 的实机耗时。普通条件用预热后三轮中位
 数；压力条件为单次观察，外部窗口到期的记录不作为已完成计算或正确性通过。

 阅读顺序：先看版本与方法，再看普通场景、压力边界和逐条件表。原始输入、逐轮结果、CSV、源码快照与复现说明均随数据包提供。

 测量口径
 每个版本、每个条件使用一个新子进程，同一条件内复用该进程。所有求解顺序执行，轮换版本顺序。普通条件保留一次冷
 查询观察，排除其后再记录三轮；压力条件不预热、只记录一次。压力覆盖候选/库存规模与复杂约束，不测试并发吞吐。完
 整请求均禁用结果缓存。

 核心时间为子进程中的求解时间。完整请求同时记录生产 Worker 入口时间与输入/完整输出的 IPC 往返时间；表格对完整请
 求采用扣除独立验证耗时的往返值。模块导入在原始数据单列，不含 UI 渲染、网络数据加载和设备端安装启动。

 校验分层：已完成结果独立核对身份/灵基、礼装份数/满破、COST 和指定锁位等；核心结果另行复算逐层取整收益。生产 Worker 的特殊机制主
 要核对版本间目标与助战代表一致性，未建立覆盖所有特殊机制的独立最优解校验器。

 外部观察窗口：每次 90 秒，不修改软件求解器超时。停止项记为未完成，不填伪造的完成耗时，也不与完成项计算加速倍数。RSS 峰值由已完成
 子进程自报；外部 RSS 采样未取得有效读数，停止项的峰值未知，不能宣称执行了自定义 RSS 上限。

 06 内存与使用建议




 内存口径
 每个条件、每个版本使用独立进程。RSS 高水位在求解结束后读取，包含此前模块、输入、冷观察与正式计算；最后一次独
 立验证/回传后的峰值未另追踪。它能比较已观测的进程高水位，不能解释为某一瞬间的纯求解堆大小。压力停止项没有取得
 可靠峰值，已标“未知”。本机存在默认 Node 堆限制，未人为扩大；本报告也不等于设备不会内存不足的证明。


 版本选择
 • 复杂约束、混合光环和较大候选：优先查看 H 与 F 在对应条件的实测；高起点能帮助剪枝，但仍需完成最优性证明。
 • 极小查询、快速返回或特殊路径：固定的起点准备成本可能抵消收益；保留关闭 AI 的选择。
 • 区间剪枝版：在若干条件有效，但不应沿用旧报告中的平均加速比例替代本轮结果。
 • 全图鉴、全部礼装、不限 COST：以压力页的完成状态为准，不能由普通矩阵推断极端条件可快速完成。


 本次结论的边界
 有限的固定输入、一次环境、普通条件三轮与压力条件单轮，均不能证明所有未来活动、所有账号和所有设备的性能。跨版本一致性与独立可行
 性/结算检查也不能替代对整个求解器的形式化正确性证明。从代码路径看，不限 COST 时预算剪枝变弱，礼装组合与同分最低 COST 的证明仍可
 能主导耗时；停止记录不能准确分摊各阶段成本。本次未改动产品求解超时。
