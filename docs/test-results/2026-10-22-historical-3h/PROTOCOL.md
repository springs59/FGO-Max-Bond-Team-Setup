# 统一测试协议

- 版本提交固定在 `scripts/historical-3h-versions.mjs`，按历史性能工作流和正式发布标签选择，保留原生求解和AI策略，不重建或冒充缺失的实验版本。
- 所有9种选择都调用各自原生 `recommendTeam`。15种输入完全复用当前全量测试的固定公开图鉴和确定性合成账号；记录输入SHA256、图鉴SHA256、求解器和模型SHA256、Git提交。历史快照的数据文件不作为查询数据。
- 三个同机分组：2.0/2.1.2/区间剪枝/当前关闭AI；2.1.3/2.1.6/当前经典AI/当前关闭AI；当前四种AI选择。每组四个进程使用四个不同核心，按条件轮换核心位置。共45个分组、180次查询，覆盖135个不同版本/条件组合；重复锚点单独保留。
- 每次查询独立限时10800000毫秒，从进入原生求解前开始计时，包含准备与AI推理；模块导入另计启动时间。父进程在到期时终止同步求解，标记超时，不能视为已证明最优。启动超过30秒、OOM、结果错误与正常超时分开。
- 每格新进程，关闭结果缓存和方案索引输入。AI采用各版本原生策略，2.0关闭AI，当前三模型分别选择其策略，不强制相同调用次数。原算法和模型文件不修改。
- 对完成的代表队伍，用当前规则重新检查身份唯一、账号拥有与形态、礼装库存/满破、COST、锁位、锁空、助战与NPC、指定收益、活动结算；比较主目标最高分。中途只有经过结算的队伍才能记为已验证可行解。
- 各版本原生返回不代表枚举全部最高分队伍。原有全部同分三小时长跑39702948902继续保留；其相同输入的完整结果作为额外最高分校验，不能以代表队伍数量或压缩替代身份数量冒充完整队伍数量。原生接口通常固定默认助战位置并压缩礼装代表；全部同分接口扩大物理编队域，可能得到更高分，这些覆盖差异单独报告。指定收益兼有锁定身份时，原生目标只统计preferSvtIds，全部同分接口还统计lockSvtIds，不能直接把两种主分值作等价检查。
- 时间比仅使用同机锚点配对，前提是两个查询都完整结束、通过结算且最高分相同。不同主机与旧归档的绝对耗时不直接混合排名。每格一轮，不宣称普遍快慢。
- 每30分钟保存检查点，结束生成Markdown/JSON；缺失、进程异常、不同输入、同目标版本间分数矛盾均令基础验证失败。对完整枚举更高分的发现，另列最优性差异并排除对应性能排名，测试执行成功不等于所有版本最优性通过。只提交数值日志、指纹和脚本，不保存全部队伍大文件，不上传原始账号抓包。
- 保留旧长跑，不合并main、不发布安装包。新工作流仅在隔离测试分支触发；结果提交使用 `[skip ci]` 防止重复三小时任务。Actions排队时间另计，3小时是每次查询上限，不是所有排队作业完成的承诺。
