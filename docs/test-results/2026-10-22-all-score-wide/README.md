# 全部最高分配队：广覆盖验证与压力测试（2026-10-22）

本轮测试三种已打包 AI（经典高起点、扩展策略、大数据神经）和关闭 AI，共15种条件、60个独立进程用例。生产求解引擎沿用 PR #19；新增测试还发现并修复了空位锁定默认字段变化导致重复查询未命中完整缓存的问题。

## 正确性与回归

- 新增1,000组固定种子独立物理槽位穷举：684,918次合法候选结算、232,234套最高分结果，逐项集合一致；879组可行，121组不可行。包含486组账号模式、514组自由图鉴、203组主练、506组带助战和167组活动加成（条件可重叠）。
- 独立穷举不调用生产搜索、上界、代表项压缩或遍历排序；身份/形态/站位/礼装及满破状态逐项比较。库存、解锁和最终结算使用软件规则。
- 原14组独立对照、Grand、NPC、大整数逐层取整、分页/导出/取消、写盘失败、查询竞争、活动窗口缓存失效等原测试仍保留。
- 本地完整 `npm test` 已通过；空位规范化修复后新增 Worker 回归通过。最终完整回归与浏览器状态以 [PR #19 检查](https://github.com/springs59/FGO-Max-Bond-Team-Setup/pull/19/checks) 为准。
- 真实浏览器新增相同条件完整归档复用，以及320/390/834/1440像素宽度检查；保留OPFS跨64套翻页、完整JSONL导出、途中队伍、软停止和后台计算不打断编辑检查。

## 起点与大量同分的实际表现

| 压力条件 | 关闭AI：45秒内当前最高 | 三种AI：已验证起点 | 结论 |
|---|---:|---:|---|
| 国服全图鉴 | 7549 | 7593 | 四种选择均未完成；AI起点更高，尚未枚举到该分数队伍 |
| 日服全图鉴 | 7523 | 7593 | 四种选择均未完成；AI起点更高，尚未枚举到该分数队伍 |

20人零分场景在45秒内分别生成5,153,068～5,337,213套同分记录，仍未列全。AI无法通过提高零分起点剪掉这些合法同分队伍。报告将“AI已验证起点”与“枚举得到的队伍”分开计数；起点先出现而枚举数为0时，不代表没有可行解。

本地引擎峰值RSS最高421.8MiB。此矩阵流式计算摘要，不保存全体队伍，也不含界面/OPFS落盘耗时；不能将该内存量视为浏览器全量归档的内存或容量保证。每格仅一次，不能据此宣布某个AI普遍最快。主练、锁定礼装、冠位或固定NPC等条件可能直接使用精确回退，实际推理次数在JSON逐格记录。

先预热，再交替运行7轮，取中位数。两组使用相同完整物理配队域，对照关闭分数剪枝；不是与旧版只输出代表解的软件比耗时。最高分、全部同分数量和指纹一致。
