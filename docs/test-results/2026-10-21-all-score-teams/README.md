# 全部最高分配队优化

实现：完整保留当前条件下所有最高主目标分数的配队；同分但 COST 更高、角色/形态/站位或礼装/满破状态不同的队伍不会被代表项替代。完全相同礼装的物理副本不重复计数。普通好友助战沿用不限从者的表示，枚举其位置与礼装；固定系统助战按给定 NPC 区分。主练模式按主练分数收集所有同分结果，次级总分仅作展示。

搜索只使用已结算可行起点和可靠上界，严格小于当前最高分才剪枝。途中已实际算出的其他合法队伍也保留；不会为补齐低分队伍继续穷举。最高分提升后，原来的最高分记录自动归入途中其他队伍。

## 实现方式

- 原有 AI 选择仍可提供可行起点；关闭 AI 时不调用模型。起点不作为最优性证明。
- 不运行一次完整旧版证明后再重复枚举；使用可行起点启动一次完整同分搜索。
- 查询准备阶段绕过仅适合代表解的 Top-N/因子压缩；保留当前筛选、库存、解锁、站位与锁定约束。
- 普通场景使用保守的角色/礼装分数上界、预算剪枝和查询内效果缓存；同分分支保留。复杂活动、系统助战、冠位场景回退到逐队精确结算，不能套用未经证明的普通场景上界。
- 支持时按页写入 OPFS，不支持时明确提示内存保存；界面每次读取 64 套；这是读取窗口，不是结果上限。支持途中其他队伍、停止后查看部分结果、完整 JSONL 导出。
- 枚举未结束、存储失败或用户停止时不会标记“全部同分配队已列全”。

## 正确性验证

14 组独立物理槽位穷举对照，全部最高分集合（共 7,376 套）逐项一致。另覆盖同分不同 COST、相同效果不同形态、礼装库存与满破、固定位置/空位、己方与助战礼装、冠位免费报酬礼装、固定非满破 NPC、满绊光环、主练同分但次级总分不同、大整数逐层取整。

分页测试覆盖超过 64 套结果、不丢失后续页面、500 个不同分数桶的部分页回写、完整导出、取消后仍可读取、磁盘失败不宣称完整，以及新旧查询初始化竞争。原有 npm test 完整回归已通过；新增用例已加入默认测试命令。

## 同机性能对照

对照组是在相同物理配队域内关闭分数剪枝的完整枚举，仍执行库存与预算约束；不是旧版仅返回代表配队的求解器。每组先预热，再交替运行 5 轮，取中位数。两组最高分、同分数量和全体同分配队指纹必须一致。

运行环境：INTEL(R) XEON(R) PLATINUM 8573C；v24.19.0。

| 场景 | 对照中位毫秒 | 优化中位毫秒 | 耗时比 | 最高分配队数 |
|---|---:|---:|---:|---:|
| conditional | 31.92 | 16.70 | 0.523 | 324 |
| tight-budget | 19.78 | 7.86 | 0.397 | 162 |
| rounding-ties | 50.91 | 45.40 | 0.892 | 6318 |
| identity-stress | 525.39 | 61.00 | 0.116 | 3888 |
| all-zero-ties | 12.31 | 12.57 | 1.022 | 996 |

条件与预算较强时剪枝有效；零分或大量取整同分时，可排除的分支较少，完整输出成本不能通过删除同分结果来消除。小规模合成对照不能外推为此前全图鉴三小时场景的加速倍数。

本轮尚未重复旧的全图鉴三小时压力矩阵。真实浏览器、Worker、OPFS、桌面/手机页面、分页、导出与停止的端到端检查已通过：[运行记录](https://github.com/springs59/FGO-Max-Bond-Team-Setup/actions/runs/39636035910)。浏览器实测完整读取 66 套同分结果，另一个查询保留 36 套最高分与 150 套途中队伍；停止测试保留部分结果并明确未完成证明。JSON 和截图保存在该运行的 `all-score-teams-validation` 附件。

数值记录：[benchmark.json](benchmark.json)。可运行 `npm run test:all-score-teams`、`npm run benchmark:all-score-teams`；浏览器检查为 `node scripts/check-all-score-teams-browser.mjs`（需安装 Playwright Chromium）。
