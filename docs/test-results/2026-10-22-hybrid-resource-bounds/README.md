## 保留的限制

- 三个模型仍由用户选择；没有添加未经验证的按区服自动路由，也没有同时运行三个完整求解器。
- 完整同分目标与历史代表解目标不同，不能用旧版少输出的耗时作为等价性能结论。
- 本次代码只在独立分支供审查，尚未合并main或发布。上述表格仍是短测结果，不能当作新三小时矩阵的最终结果。

## 授权后的三小时验证

独立分支 `optimize/hybrid-resource-bounds` 包含专用工作流 `Hybrid resource bounds three-hour comparison`。15种相同条件 × 4种AI选择 × 资源剪枝开关，共60个同机配对、120种查询配置。普通条件各重复三轮，三个压力条件各一轮；每次查询独立限时10,800,000毫秒。

每个分组同时运行两个全新求解进程，固定到不同CPU核心；重复时交换核心。依据宿主机及cgroup内存的较小值分配堆，每进程最高6 GiB，预留系统空间。只在两侧完整结束且最高分、方案组数量和指纹一致时给出耗时比；超时、进程失败、内存不足、结果缺失和不一致单独标记。

启动自检覆盖完整结果、1毫秒超时、CPU绑定、缺失分组和不一致检测。完整原始记录与合并后的JSON、Markdown报告保存在该次Actions的产物中，保留90天；报告生成不会自动写回源分支，避免重复触发长测。
