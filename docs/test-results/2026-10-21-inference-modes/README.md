# 按模型原生用途验证推理方式（2026-10-21）

本轮没有发现足够稳定的收益，支持把现有三款模型从单次查询决策改为分域重推理。推荐 H、T、N8192 继续使用各自原生的整查询策略决策；原框架神经头按逐候选评分另列参考，评分去重减少调用，但没有稳定的总耗时改善。当前三款权重、软件默认选择和安装包均未改动。

## 范围与正确性

- 9 组配置：不使用 AI；H/T/N8192 各自的单次全查询、按不同特征子域重新推理；原框架逐候选、按特征去重。
- 18 个校准条件＋32 个主复核条件＋8 个固定助战礼装差异补充条件＋4 个压力条件，共 62 个条件。58 个普通条件均完整完成。正式计时 2646 次；普通条件每组预热 2 次、正式 5 轮，压力每组冷观察 1 次。
- 另有 320 次精确对照及调用计数检查通过。58 个普通条件、已完成的己方六人压力条件，其收益、COST 及适用核心条件的全部助战/位置最优均一致。核心方案另做独立取整羁绊结算；完整请求核对多目标结果及合法身份、形态、库存、位置、COST。
- 关闭结果缓存，顺序求解，轮换配置先后顺序。核心报告求解耗时；完整请求报告扣除独立校验耗时的 IPC 往返，包含输入/结果复制，导入单列。模型校验、推理、固定规则及精确搜索均计入各自完整耗时。

## 为什么不能强行使用同一种推理接口

H 使用 18 维整域特征，T 使用 60 维，N8192 使用 84 维；它们输出固定策略选择。原框架的双神经头使用 16 维单候选特征，输出优先级。框架组仅恢复旧神经头的排序用途，其余沿用同一精确求解器，不代表旧版软件整包性能。不能把 N8192 的整域权重直接套到逐候选接口，也不能把 T 的单次树冒充原框架网络。

分域版按模型实际使用的特征向量缓存决策，仅输入变化时再推理；相同输入仍复用。原框架去重版按候选类型和完整特征缓存神经头输出，检查其数值与原输出完全一致。所有学习输出只影响遍历或选择经数学证明安全的界，不直接删除可能最优的分支。

## 真正改变子域的补充组

空装备 NPC 的重复输入没有触发额外推理，故补充 8 个固定礼装不同的助战条件：先 4 个探索校准，另 4 个独立复核，改变羁绊基数、COST、固定礼装加成，并覆盖紧凑求解与通用搜索。该组是后补诊断，独立报告，不冒充原始盲测。

三款模型都实际从每查询 1 次增加到 3 次，原框架从 21–28 次降为去重后的 6 次。补充校准组的一次导出不完整，原记录保留并整组弃用；最终报告使用重新完整测量的 4 条件。补充复核已先行测量，因此这次重测只作诊断，不用于重新选择或调整模型。

| 模型 | 补充探索组合计变化 | 补充独立复核合计变化 | 复核几何比及 95% 区间 |
|---|---:|---:|---|
| 经典高起点 AI（H） | -0.94% | -2.44% | 0.948 [0.862, 1.041] |
| 扩展策略 AI（T） | -26.45% | +3.74% | 1.056 [0.824, 1.406] |
| 大数据神经 AI（N8192） | -23.00% | +1.59% | 1.009 [0.952, 1.058] |

T 在补充探索组看似更快，但独立复核没有复现；H 的微小改善也不稳定。增加调用次数或减少调用次数，都不能单独证明最终查询更快。

## 选择规则和数据边界

原生方式是默认候选。首次校准阶段预定：条件等权几何耗时比 <0.97、按条件配对重采样的 95% 区间上界 <1、合计耗时不得增长超过 5%；分域版还须至少两个条件确实触发多次推理。初始选择在主复核之前冻结，四项候选均未达到采用门槛，见 selection.json。补充组用于检查漏测的实际多域行为，不重新调参。区间按 5000 次固定种子条件配对重采样生成，仅反映本矩阵，不代表所有设备或用户输入分布。

主复核包括 16 个新公开图鉴/未见合成组合、4 个新多助战配置及 12 个历史条件；并非全部条件都从未用于以往实验。校准、复核和模型训练种子不同。未重新训练、改权重或根据复核数据选叶子。

执行代码与 2.1.6 源码提交 2d21ebd76b14139051af9f4dad9b926d6aad0577 核对，271 个 src 文件相同，包括全部 JavaScript 与三份权重；JP bundle/metadata 使用此前归档的固定快照，并非 2.1.6 当天最新 JP 数据。所有配置共享该快照，JP 原始数据已随私下保留的原始包保存，CN 使用上述公开提交的数据，详见 source-verification.json 与 runtime-manifest.json。该实验是 Linux/Node 对照，不是 Android/Windows 实机性能测量。

最初计时与独立校验重叠，随后一次终止未确认的计时也被弃用；另有补充组导出不完整。均保留于 discarded-attempts.json.gz，不与正式数据拼接。正式计时阶段没有同时运行独立正确性测试。

## 复现

先取得并解压上述原始包至 /tmp/fgo-inference-fixtures。完整仓库克隆保持本次日志提交中的 JavaScript 版本，再依次运行：

```bash
npm ci
export FGO_INFERENCE_FIXTURES=/tmp/fgo-inference-fixtures
python scripts/inference-modes/prepare.py /tmp/fgo-inference-modes
node scripts/inference-modes/check.mjs /tmp/fgo-inference-modes
export FGO_INFERENCE_CASES="$FGO_INFERENCE_FIXTURES/cases.json.br"
FGO_INFERENCE_STAGE=calibration node scripts/inference-modes/run.mjs /tmp/fgo-inference-modes
python scripts/inference-modes/summarize.py /tmp/fgo-inference-modes select
FGO_INFERENCE_STAGE=holdout node scripts/inference-modes/run.mjs /tmp/fgo-inference-modes
FGO_INFERENCE_STAGE=domain-calibration node scripts/inference-modes/run.mjs /tmp/fgo-inference-modes
FGO_INFERENCE_STAGE=domain-holdout node scripts/inference-modes/run.mjs /tmp/fgo-inference-modes
FGO_INFERENCE_STAGE=stress node scripts/inference-modes/run.mjs /tmp/fgo-inference-modes
python scripts/inference-modes/summarize.py /tmp/fgo-inference-modes final
```

两条完整输入（核心＋生产 Worker）已通过保存的压缩数据回放，覆盖全部 9 配置。各步骤顺序完成后再执行下一步，勿同时运行测试或另一轮计时。prepare 从固定公开提交恢复 CN 数据，并从原始包恢复 JP 数据，仅写实验目录；对不同 JavaScript 版本或数据摘要会拒绝复现。实验变体不写入 src，不自动替换发布版。
