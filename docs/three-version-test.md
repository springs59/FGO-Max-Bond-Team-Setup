# 羁绊三版本对比测试 APK

一个 APK 内包含 2.0.0、2.0.8 和 2.0.9 优化测试版，返回选择页即可切换。独立包名 `cc.fgobond.compare`，可与正式版共存。仅在 `test/three-version-209` 分支构建，不合并 main，不更新正式版或 Pages。

三版本使用同一份 2.0.8 发布时的游戏数据。2.0.0 / 2.0.8 使用对应发布提交的求解代码；统一附加耗时观察器。账号、数据库、方案库、OPFS 临时文件和缓存通过不同来源地址隔离。请分别导入同一个账号。测试包关闭自动数据与软件更新，避免测试期间数据变化。

2.0.9 包含：只在初始化及替换时发送静态图鉴；小消息有容量检查的轻量传输、大消息继续 64 KiB 确认分块；静态查询键编码复用；最多四项、约 2 MiB 序列化大小的已校验查询缓存，每次命中仍读取元数据检查更新、删除和歧义；进度消息限频。求解规则、所有 COST 选项、手动保存及崩溃恢复机制保留。本测试版仍返回完整结果，尚未加入详情按需分页。

## 建议测试方法

1. 每个版本导入相同账号，选择同一区服、关卡、基数、COST、礼装和编队限制。
2. 分别记录首次计算，随后相同条件重复至少五次。2.0.8 / 2.0.9 如要测已保存缓存，请先主动选择保存临时结果。未保存时的再次计算要单独看待。
3. 修改基数、COST、任意从者位、账号或筛选条件，检查耗时与队伍结果是否及时变化。允许任意 COST；自动验证中的 COST 95 仅为对照条件。
4. 交替测试版本顺序，避免温度、电量和系统后台任务影响比较。优先看同一人的同一设备、相同条件下的多次中位数。
5. 返回版本选择页，填可选测试者代号，点击“导出三版本测试记录”。把 JSON 和现象说明发给项目维护者。最近 300 次记录保存在本机，不会自动上传。

顶部耗时从发出请求开始，至完整接收并解码结果结束；包含传输、缓存检查、曲线处理及实际求解，不含界面渲染、图片加载和用户手动保存。显示缓存是否命中。冷启动和重启 Worker 的耗时应另行比较。

报告含设备型号、Android / WebView 版本、测试者代号、条件摘要、数量、总分、缓存命中及耗时；不写入账号抓包原文、账号密码或完整持有清单。请勿在代号中填写隐私信息。

这是测试版本，2.0.9 尚未作为正式版本发布。三版本自动验证使用有限样本，不能替代真实设备与完整账号测试。预计算仓库扩容保持暂停。

## 构建前验证

全部项目单元测试通过。浏览器检查使用 30 / 120 名从者、相同 34 张羁绊礼装、三种轮换版本顺序，共 216 条测量记录；所有版本对照样本的总羁绊一致。每组相同 Worker 重复 15 次，另测重建 Worker、冷查询和修改基数。

| 从者数量 | 版本 | 同 Worker 重复中位数 | 重建 Worker 中位数 |
| --- | --- | ---: | ---: |
| 30 | 2.0.0 | 20.30 ms | 87.20 ms |
| 30 | 2.0.8 | 85.20 ms | 137.80 ms |
| 30 | 2.0.9 | 7.90 ms | 77.20 ms |
| 120 | 2.0.0 | 37.70 ms | 120.20 ms |
| 120 | 2.0.8 | 155.60 ms | 242.30 ms |
| 120 | 2.0.9 | 11.10 ms | 169.10 ms |

以上为本次 Linux Chromium 153 上的有限浏览器样本，带统一观察器，不能代表 Android 手机速度。2.0.9 的 120 从者修改条件中位数仍约 2.94 秒，曲线处理及搜索未获得同等幅度优化。原始记录保存在 `docs/test-results/three-version-local.json`。Android 模拟器检查另在构建流程执行，失败则不发布测试 APK。
