# 冠位大库存搜索与无收益礼装修复（2026-10-25）

用户反馈：未锁定的位置被补入没有羁绊效果的低星礼装；冠位杀仍显示“搜索更高收益”，数小时停在 49522，曾在旧版见过 50894。历史记录没有保存该队伍或完整条件，本次没有用公开样本冒充用户账号，也不能把 50894 与任意公开样本直接比较。

## 已确认的原因

- 完整结果域原先包含所有库存礼装，连没有羁绊效果的礼装和可选羁绊礼装位也作为同分物理差异收集。它们会占 COST、扩大组合和让推荐看起来像在凑 COST；COST 本身不是优化目标。
- 2.1.14 的礼装优先路径先准备全部完整礼装组合，再开始结算从者。大量礼装导致两两支配比较触及准备上限时，整个路径会回退，没有先给出有价值的高分起点。上一轮真实图鉴测速只取前四类羁绊礼装，未覆盖这一大库存形状。
- 固定己方普通／奖励／羁绊位或助战礼装会直接禁用新路径，回到逐队枚举。
- 仅固定助战奖励礼装时，普通域没有同时固定助战所在位置；本次一并修复。

## 改动及精确性

自动编队不再补入没有羁绊效果的礼装；对当前队伍完全不命中的普通团队效果也留空。羁绊位不增加通关羁绊，未锁定时留空。英灵肖像等有实际效果的低 COST 礼装继续参与搜索，效果相同的不同礼装身份、满破状态和更高 COST 的有效同分方案继续保留。明确锁定的礼装始终保留，包括零收益普通／奖励／羁绊礼装及系统固定装备；未绑定从者的同一钉选需求不会被重复填到多个空位。

大库存改为按完整效果与 COST 分组处理实际库存，逐组计算可行礼装前缀。只有在处理了完全相同的库存前缀、未来可用库存相同的情况下，才允许“COST 不高、普通位不多、奖励位使用不多、每个候选收件人的效果均不低”的前缀替代另一个。每组普通位与免费奖励位合计消耗真实副本数。满破／非满破、不同身份的物理恢复仍由完整收集阶段负责，没有把减枝后的身份子集当作完整答案。

准备各组时就结算一些可行高收益队伍，让后续搜索使用更好的已核实下界。预览只选择部分候选用于排序，最终最高分证明仍检查全部无损合并后可行组合；预览数量限制不会成为答案上限。每次进步都由原始精确结算复核，不一致则回退一般求解器。

固定礼装先按实际 ID 和满破状态预留库存，再优化剩余普通与免费奖励位。重复钉选同一从者同一礼装只占一份；冲突钉选、共享不足和 COST 不足仍拒绝。助战普通／奖励位分别尊重锁定及同 ID 限制。查询内上界缓存和已解组合缓存均有容量限制，不写逐候选日志。保留取消让步点，没有新增用户查询时间上限。

AI 模型及权重不变；AI 仍只参与排序，每次查询最多推理一次。不满足精确快速路径前提的活动、复杂编成、负效果、自身效果等仍按完整的一般求解器处理。

大库存样本的三轮测试中首次达到不低于 50894 的中位时间约 0.37 秒。该阈值只是用于观察找到高分的速度，不代表复现了用户的 50894 配队。

测速使用同一份当前国服公开图鉴和完全相同的输入：B=4748、COST≤116、全部可用杀阶从者、每类羁绊礼装一份满破，另加 80 类无羁绊效果库存。不同变体分别固定冠位、助战礼装或己方普通与奖励礼装。每个样本使用新进程，关闭 AI 和结果缓存，旧版加载 2.1.14 的求解代码，新版加载本分支代码。包括准备和预览精确结算，不包括 UI、Worker 调度与 OPFS 归档；10 秒截断不是最高分证明。源码哈希和完整输入哈希在机器报告中记录。

表内时间是**最高分证明耗时**，不是全部同分队伍收集耗时。完整有效同分集合用独立小域穷举、随机对照和浏览器导出回归验证；没有宣称大图鉴全部收集已在表内时间完成。

## 验证及复现

- 新路径：152 个独立案例，288 次强制新路径证明，22,327 套完整有效最优物理队伍。包含大于六组礼装、共享库存、满破变体、固定普通／奖励／羁绊装备、助战仅奖励锁定、不同灵基、光环及主练目标。
- 1,000 组独立随机对照：112,750 套有效最优物理队伍，402,974 个精确结算叶子；旧版仅靠无效果礼装产生的差异按新要求不再收集。最大收益及完整有效同分集合均一致。
- 105 个独立 Grand 案例、288 个可行性对照、特殊关卡与多冠位共享库存回归通过。
- 10 个专门的“无用礼装留空／有用低星保留／明确锁定保留”案例，共 414 套物理队伍。
