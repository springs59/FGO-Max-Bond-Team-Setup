# 按对应职阶判断冠位（2.1.24）

修正 2.1.23 将账号任意冠位作为统一开关的错误。根据账号完整冠位名单与完整图鉴，先确定已选择冠位的职阶/冠位栏，再对当前合法候选启用推荐。

| 情况 | 行为 |
|---|---|
| 所需职阶已有冠位 | 只使用该职阶真实冠位 |
| 已有对应冠位被特性、库存筛选、锁定或允许位置排除 | 不推荐替换；必须冠位时无合法队伍，可选规则保留普通队伍 |
| 只有其他职阶已有冠位 | 不阻止所缺职阶推荐 |
| 所需职阶无冠位 | 推荐当前持有的合规人选，标明需先选择冠位 |
| 关卡允许多个冠位职阶 | 按各职阶分别判断，真实冠位与缺失职阶的条件推荐可同时出现 |
| Extra I / II | 各自按照共享冠位栏判断 |

普通冠位、特殊编成与导出报告共用规则。判断不使用筛选后的冠位名单，不修改账号记录。账号区仍展示完整真实冠位名单，提示更新为对应职阶规则。保留前序全位置搜索、方案库、导出格式、阶段状态和缓存修复。

验证：54 组冠位策略检查通过，含新增 36 组七职阶和 Extra I / II 对照；涵盖其他职阶有冠位、同栏已有冠位被排除、普通/特殊编成、导出标记、账号不变和 Extra 同栏不可双选。完整 npm test 已通过。页面自动化新增两类已有其他职阶冠位的必选/可选场景及条件报告导出。

本地浏览器启动受运行环境套接字限制，新增页面场景交由仓库 CI Chromium 执行；不将本地无法启动记作页面通过。安装、升级与 Android 模拟器验证由现有原生发布流程执行。
