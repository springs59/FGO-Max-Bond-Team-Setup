电脑和安卓共用配队规则，分别保留国服、日服数据。

Windows：运行 EXE 安装。关闭主窗口后在托盘继续运行，从托盘打开“更新与后台任务”。退出软件会结束后台任务。安装包目前未使用商业代码签名证书。

安卓：下载 Release 附件中的 APK 安装。发布的 APK 已通过签名校验，并沿用原安装包的签名证书。任务通过 WorkManager 在后台执行，通知栏显示进度及暂停操作；自动检查由系统调度，允许中断和继续，不承诺持续唤醒手机。

界面：顶部“界面设置”可切换橙棕色版、白色版，以及一页式、分区多页式布局。两类选择可以自由组合。可自定义页面背景、面板、文字与强调颜色，上传本地背景图片，并恢复主题颜色或移除图片。设置在本机保存，刷新、切换区服和配队模式后仍保留。

推荐：保留不同助战礼装作用与助战位置下的队伍方案，按羁绊收益排序；通过左右翻页、卡片或列表切换，查看各方案与可替换成员。账号库存、COST、满破和关卡条件仍分别校验。

数据更新：每 6 小时检查已发布的验证快照。目录锁定源提交，逐文件校验 SHA-256，只下载变化的文件；全部通过验证及本地预计算后原子切换。失败保留旧数据，暂存步骤可恢复。

预计算：在本机分别生成、校验 CN/JP 的从者灵基、礼装作用与组合因子索引。完整曲线、活动矩阵和预计算队伍索引复用 Actions 的已验证产物；数据版本相同则复用本地索引。账号限制配队仍由本机精确求解，并非枚举并永久保存所有账号的所有队伍。

离线：图鉴和配队数据包含在安装包内；首次无网络仍可计算。立绘当前使用在线资源，未浏览过的图片无网络时不保证显示。

隐私：账号抓包和导入信息不会用于更新请求，不发送到 GitHub 或第三方计算服务。

开发：先运行 `node scripts/build-native-assets.mjs`；桌面端 `cd native/desktop && npm ci && npm start`；安卓端以 JDK17、Gradle8.11.1 构建 `native/android`。Android 8 以上，须有支持模块 Worker 的较新系统 WebView。签名密钥不进入公开仓库。

验证包含：双区服本地预计算、未变化数据不重算、损坏下载拒绝发布、中断恢复、原子提交、页面固定数据版本、Windows 后台任务启动、Android 模拟器后台预计算，以及现有网页回归测试。

自动发布：仅在 Actions 中手动运行“完整更新并发布安装包”工作流时发布。它先完成国服/日服数据更新、全量预计算与验证，再锁定验证后的提交构建 EXE 和 APK；两端测试和安卓签名校验全部通过后，将安装包与 SHA256SUMS.txt 同时发布到对应版本的 Release。普通主分支提交、每 6 小时刷新、每周深度刷新，以及单独运行安装包构建工作流都不发布。验证分支只构建和测试。全量更新前检查签名配置，缺少密钥时明确停止，不覆盖现有 Release。

操作入口：Actions → 完整更新并发布安装包 → Run workflow → 选择 main。安卓签名密钥只需首次配置，之后发布过程由 Actions 完成。

版本递增：每次新触发大更新，使用该工作流的运行序号递增补丁版本和 Android versionCode。已发布的第 1 次为 0.1.0，第 2 次为 0.1.1，随后为 0.1.2、0.1.3。失败的运行可能留下版本号空档；重跑同一次运行沿用原版本号。两端版本在构建时同步写入，仓库中的 0.1.0 是计算基准。先创建草稿，EXE、APK、校验文件全部上传并检查后才公开新 Release；旧版本保留，只允许同一次运行重试自己的附件。不要修改版本基准或重置大更新工作流的运行序号。

维护者首次设置：在仓库 Settings → Secrets and variables → Actions 中设置 `ANDROID_SIGNING_KEY_BASE64`（原 PKCS12 签名密钥文件的 Base64）和 `ANDROID_SIGNING_PASSWORD`（原密钥密码）。密钥别名为 `fgo-bond`，证书指纹必须匹配现有 APK。密钥及密码不得提交到仓库。
