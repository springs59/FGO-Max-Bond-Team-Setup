# 数据更新时联合与多账号

软件构建只复制已经验证的代码和数据。礼装命中向量、活动效果和编队条件的联合在数据更新任务中完成：公共数据更新由 `scripts/update-joint-effects.mjs` 执行，两区服本地后台更新由 `native/shared/task-worker.js` 执行。

公共联合索引保留每个从者身份和灵基。一个效果组引用所有匹配成员；效果相同不会丢弃身份。基数不参与联合键，基础羁绊仍在查询时作为变量结算。索引是完整组合要素的表示，不是只保留全局最优或前 N 名的队伍列表。

账号层先根据本机账号的持有身份、解锁灵基和库存筛选公共范围。查询再应用 COST、锁定成员、空位、助战及关卡规则，并调用现有精确求解器。账号投影和最终推荐均分账号缓存。投影不是所有预算和锁定条件的预存最优队伍，也不绕过最终结算复核。冠位、固定 NPC 和原求解器不支持的特殊规则仍保留原有回退或明确提示。

## 多账号操作

- “导入新账号”新增记录，支持一次选择多个文件；Chaldea 文件中的多个 users 分别导入，不合并库存。
- “当前账号”切换本区服的已保存账号；每个账号独立保存基础羁绊、关卡、COST、筛选、锁定、茶壶和配队模式。
- “更新当前账号”仅替换当前账号的库存与状态，保留名称、设置和账号标识。
- 名称可以编辑。删除只影响当前账号；若仍有同区服账号，会切换到另一账号。旧单账号记录自动迁移。
- 账号导入和变化会请求本机后台更新投影；账号信息不会进入公共索引，也不会发送给更新服务器。

## 是否需要预计算

基础数据、活动有效状态、活动适用内容、关卡编队规则和账号状态均参与复用校验。

| 变化 | 更新范围 |
| --- | --- |
| 公共数据及账号均未变化 | 无需预计算 |
| 仅新增或更新账号 | 使用当前本机数据，只生成该账号尚未缓存的投影 |
| 仅活动有效效果变化 | 复用基础礼装／身份因子，更新联合效果和相关账号投影 |
| 从者、礼装或基础数据变化 | 重新生成受影响区服的公共索引和账号投影 |
| 编队规则变化 | 更新相应条件的联合索引 |

活动开启、结束或适用对象／数值变化会使旧联合索引失效。更新中遇到不支持的机制或校验失败，继续保留上一份完整数据；查询不会把旧活动联合索引视为当前有效答案。

任务中心显示“需要预计算／无需预计算”、账号数量和预计耗时范围。第一次使用工作量模型作初步估算，后续根据本机最近的实际记录校准；下载时间单独计算，估算不是固定承诺。任务仍可暂停和继续。更新完成后使用“加载已完成的数据”切换版本，当前打开的页面保持同一份数据快照。

## 验证和发布状态

新增验证涵盖多账号迁移、库存和设置隔离、多用户文件拆分、活动／关卡／区服／时间边界失效、完整身份覆盖及联合结果与原精确求解器的对照。后台更新验证包括账号单独更新不访问网络、仅活动变化时复用基础因子、损坏数据拒绝发布及原子切换。
