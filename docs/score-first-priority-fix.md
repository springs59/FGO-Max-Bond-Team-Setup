# 修复高收益搜索顺序退步

v2.1.10 在部分冠位输入中比改动前更晚找到较高收益。原因是成员排序缺少礼装命中信息，低 COST 的无命中成员会排在前面；满羁绊光环提供者的价值按整队受益高估，可能先选出缺少实际收益对象的队伍。选定成员之后，深度遍历又可能长时间停留在这组成员的礼装与助战组合中。

本次保持当前精确求解器、“先提高收益并证明最高分，再补全全部同分”流程及全部关卡约束，修改如下：

- 将已持有礼装的属性命中、库存副本与满破状态，以及助战礼装命中纳入成员访问顺序；降低对满羁绊光环提供者的孤立估值。主练目标只把目标从者计入直接收益。估计仍是启发式，不能作为分数剪枝依据。
- 礼装排序先为每张卡计算一次候选队伍收益估计，再排序；缓存属性匹配，复杂域在试探、完整优化和同分收集之间复用。安全普通域复用已有精确上界效果表。没有好友位的布局不再计算无用的好友礼装排序。
- 较大的复杂域先有预算地试探多个候选队伍。每组成员最多试探 8 个完整组合或 128 个装备节点；每个域最多试探 64 个完整候选、4096 个节点或约 150 毫秒探索时间，到协作点检查预算。探索时间从成员遍历开始计算，不包含完整搜索也需要且会复用的一次礼装缓存准备。小输入与恢复搜索跳过此额外试探。
- 试探仅提交精确结算通过的合法改善队伍。之后完整遍历从根开始，使用独立库存计数；试探结束不代表无解或最高分已证明。同分收集仍完整进行，试探中的最终最好队伍不会重复归档。停止时保留最好预览，包含尚未来得及归档的情况。

缓存按查询域弱引用管理，大小取决于输入的礼装与从者形态数量，不随搜索节点或同分队伍数量增长；不增加磁盘临时文件。不切换旧方案、不训练或更换 AI 模型。

## 复现对比

原始数据见 [score-first-pressure-benchmark.json](score-first-pressure-benchmark.json)。三种实现使用相同的当前数据和输入，关闭 AI，在独立 Node 进程中交替运行，每个样本约 2 秒，重复三次取中位数。协作式停止可能略超时；原始报告记录实际时间。此测试不含 Worker、归档和 UI 开销。

“改动前”为 `4a07d846bdcf85eda8e716d23b5191aa818a7068`（含固定冠位联动修复的分支），不是原封不动的 v2.1.9 安装包。“v2.1.10”为发布源码，相关求解模块与 main `fb43c3d706d95268eb7b9d11e16ee67fadb29cab` 一致。

下面比较预算到期时已找到的最好收益，不将其冒充已证明最高分或全部同分已经收齐。真实数据样本使用构造账号，不是用户实际账号；主练样本的目标值只统计主练从者。

| 样本 | 改动前 | v2.1.10 | 本次优化 |
| --- | ---: | ---: | ---: |
| 真实数据冠位 | 30571 | 26585 | 42950 |
| 条件礼装冠位 | 50131 | 29242 | 50131 |
| 冠位主练目标 | 6770 | 13329 | 15894 |
| 固定后排冠位 | 29240 | 26585 | 42381 |
| 真实数据普通 | 4436 | 4436 | 4436 |
| 活动加成小样本 | 5965 | 5965 | 5965 |
| 扩展出战人数 | 1956 | 1956 | 1956 |

活动小样本没有提速：同样达到 5965 分，首次到达的中位数约 17.4 → 22.3 毫秒，完整耗时约 0.726 → 0.762 秒。复杂场景早期收益明显改善，不代表每个小输入都变快。

复现命令（准备对应版本的源码目录，共用相同数据）：

```sh
FGO_SCORE_BASELINES='{"previous":"/absolute/previous/src/recommend.js","v2.1.10":"/absolute/v2110/src/recommend.js"}' node scripts/benchmark-score-first-pressure.mjs
```

可通过 `FGO_SCORE_CASES`、`FGO_SCORE_ROUNDS`、`FGO_SCORE_BUDGET_MS`、`FGO_SCORE_OUTPUT` 指定样本、轮次、预算和输出。压力对比不设置机器相关的毫秒门槛，另有确定性节点预算回归测试，要求在前 100 个节点内找到已知的 50131 分合法见证，防止再次优先耗尽低收益成员分支。

## 正确性与限制

- 全套 `npm test`；1000 组随机独立穷举对照：684918 个参考完整组合，232234 套最优物理队伍一致。
- 新增带试探的 5 组独立物理穷举对照，1476 套最优队伍一致，涵盖总收益/主练、COST、固定冠位、扩展人数规则、库存、满破、满羁绊成员，以及跨试探和收集的去重。
- 注入试探遗漏最终赢家和空试探，验证完整搜索仍能找到赢家，且试探结束不会被当作最高分证明。
- 真实 Chromium/Worker/OPFS 验证：完整同分与分页、导出、停止、固定冠位联动、NPC 阶段，以及证明反例恢复。

此次改善早期提分，不承诺所有输入都更快完成。冠位、复杂 NPC 与实时活动等缺少安全分数上界的情况，完整最优证明和收集全部同分仍可能耗时很长。试探不会提高数学证明能力；活动效果、COST 和编队是否合法始终以原精确结算为准。
