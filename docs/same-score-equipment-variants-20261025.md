# 同分从者与礼装浏览

之前的入口只按从者成员集合切换，不能直接浏览“从者相同、礼装不同”的同分队伍。现在提供：

1. **换不同从者组合**：下一队必须有不同的己方成员集合，礼装可能随已收集方案变化；不把单纯换位或换灵基当成新成员集合。
2. **从者不变，只换礼装**：保持当前每个位置的从者、灵基、助战与冠位身份，浏览不同礼装 ID、满破状态、普通／羁绊／报酬栏的分配。
3. **查看其他同分方案**：包括从者、灵基、礼装和站位的实际变化，能查看从者与礼装均不同的队伍。

“同分”按照当前选择的优化目标（总羁绊或主练羁绊）判断。每套显示的是精确结算后的实际队伍，可直接加入对比和导出。

## 完整性和资源

- 浏览所有已收集方案组，跨越结果页，不以当前页或当前组作为全集。完成收集后可逐套读到全部保留的物理方案，不加 top-N 截断。
- 等效族按需展开，固定从者时先缩小成员池并在换位时检查固定身份，避免先展开其他无关成员。角色唯一、己方普通/羁绊/报酬栏共用库存、礼装满破库存和助战限制保留原约束。
- 每次只保留一页和当前迭代器，每种浏览方式仅保留一个游标；不建立全部展开方案或完整历史去重集合。完全相同的礼装副本不重复展开。
- 最高分已经证明但归档为零时，先利用合法见证的等效族，以及固定队伍上的单张替换/两栏交换，精确核实同分、库存、钉住礼装、有效收益和 COST。这只是提前提供可用替换；其他组合仍由完整主搜索收集，不把这个有限邻域声称为完整。
- 同分仍在收集时提示“暂未找到下一套，仍在补全”；停止或完成后分别说明已有部分方案/已收集方案已浏览完。游标能继续读取后来追加的方案，无需从第一页重扫。
- 可停止当前同分查找，也可从头浏览。取消或迟到回复不会覆盖当前选择；最高分更新后旧请求失效。操作不重新启动主查询，不增加 AI 推理次数，也不改变主搜索计数。
- 主搜索保留原零收益礼装处理，不为了凑 COST 添加无用礼装。

## 对比和保存

推荐区切换后，加入对比和各格式报告均保存当前实际选择的礼装，不回退到方案组的原代表。完整 JSONL 除原有所有组和等效目录外，也可保留当前显示队伍；提前停止时仍包含可行见证、COST、逐位收益与未收齐标记。

打开完整 JSONL 档案后，也能在组内固定从者换礼装、展开其他成员/礼装组合，以及导出当前选择。展开使用档案内的等效目录与库存约束，不创建 Worker 或重跑查询。保存时的组总分和 COST 保持不变；未单独保存的展开方案逐位收益与羁绊等级明确显示“未保存”，不把未知值填成零。缺少替换目录的旧档案仍可阅读其代表队伍。

## 验证

`score-team-variants.test.js` 将全量物理队伍及固定成员的所有礼装变化，与不合并的逐套枚举结果比较：6 类场景、1681 套展开方案，覆盖不同卡片、满破库存、普通/冠位报酬/羁绊栏、助战、钉住、主练目标、零归档见证、报告快照、64 组跨页、追加部分尾部、取消/重置与原搜索计数不变。

`check-score-team-variants-ui.mjs` 使用真实页面与 Worker，验证固定成员换礼装、成员和礼装同时变化、两队对比、当前所选礼装报告、离线 JSONL 展开和导出、不启动新查询、取消迟到读取以及 320/390/834/1440 布局。所有提交夹具均为公共合成数据，不包含用户账号或抓包。
