# 其他关卡的首套结果与约束冲突检查

本轮按要求暂停 main 合并与发布，检查“节点持续增长，却长期没有完整组合”的共用路径。截图未展示账号及全部条件；以下是可重复的同类故障与测试范围，不声称还原截图中的具体查询。

## 另外确认的故障

这些问题不限于冠位，普通、活动、无助战、固定好友和系统 NPC 都会进入同一枚举器：

| 条件 | 修改前的观察 | 修改后 |
|---|---|---|
| 必须自出六人，但只有五个可用身份；每个身份有多个形象 | 8,192 节点，完整组合 0，达到观察上限 | 布局展开前识别人数不足 |
| 两名从者指定同一礼装，库存仅一张 | 8,192 节点，完整组合 0，达到观察上限 | 搜索前检查实际副本需求 |
| 指定穿戴礼装，但账号库存为零 | 8,192 节点，完整组合 0，达到观察上限 | 搜索前识别缺失库存 |
| 最后一个位置锁定高 COST 礼装，必选从者与礼装已经超预算 | 8,192 节点，完整组合 0，达到观察上限 | 展开前检查最低必要 COST |
| 同一从者同时指定两张不同普通礼装 | 8,192 节点，7,224 次末端检查，但没有合法结果 | 搜索前识别互斥约束 |

上述五个合成故障在修复后均为 0 个展开节点即结束。修改前运行的是本轮修改前的 PR #22 枚举器，而非声称等待所有旧查询穷尽；8,192 是观察停止上限，不是旧版总耗时或总节点。

副本需求按实际穿戴字段计算：槽位钉选和同从者礼装钉选的重复记录只计一次；两名不同从者各需一张；“至少一名从者穿戴该礼装”可与已指定穿戴者共用；冠位报酬、羁绊装备另外消耗副本，但不计普通装备 COST。剩余成员按不同身份计数，不把同一从者的多个形象算作多人。装备递归为后续必选字段预留库存与最低 COST，避免可选装备提前耗尽它们。

全部检查仅使用无解的必要条件或向下放宽的 COST 下界。保留当前精确搜索与全部同分方案；不切换旧算法，不设 top-N 截断。

## 验证结果

- 12 类规则组合：普通、活动自身加成、活动全队加成、全关卡活动、无助战、固定前/后排好友、无固定礼装/有固定礼装的 NPC、自出六人、全队六人、冠位。288 组独立小规模物理穷举，104,304 套合法零分队伍逐套一致；分别验证字面搜索与等价分组展开。覆盖绑定/不绑定穿戴者、重复钉选、库存与 COST 冲突。
- 61 组大名单无解组合均在少于 64 节点内完成无解判定；另测有限库存的后排必选礼装仍能得到合法起点。
- 447 个公开国服从者，12 类关卡规则、8 类条件、4 种 AI 选择，共 384 组：240 组有解，144 组预设冲突。有解均得到精确结算通过的起点，无解均明确结束。最多 19 节点，本轮本机最长约 2.21 秒（含同步准备/AI 起点）；并行运行其他回归时测量。此矩阵使用真实图鉴和合成的规则组合，不等于对每条实际关卡完成最优证明。
- 原冠位真实图鉴矩阵 196 组仍通过，最多 37 节点。1,000 组随机独立穷举仍保留全部 232,234 套同分队伍。
- `npm test` 全部通过；实际 Chromium 页面/Worker 的停止、分页、导出、缓存、首个预览保留与冠位手机宽度回归通过。浏览器是移动视口测试，不是实体手机测速。

压力测试入口为 `scripts/check-quest-score-feasibility.mjs`，与冠位矩阵一起加入 CI。独立穷举在 `src/solver/score-team-feasibility.test.js`，共用的测试 oracle 不调用生产剪枝或等价编译逻辑。

| 日服 jp-extra-quests | 3,192 | 2,531 | 661 |

804 条被拒绝记录逐一经过实际查询准备验证，未进入节点枚举。主要包括精确 1～4 人、指定身份/特性与出场位置、全队固定助战等当前尚未支持的限制。该行为已有，不代表本次新增了这些规则支持。

“解析器可识别”仅指本次编成元数据分类，不保证每个 NPC 已解锁或详情完整，更不代表每条关卡已完成最优求解。缺少 NPC 详情/解锁条件、多名必选 NPC 和未知规则另有明确拒绝测试。

完整搜索在大量合法同分队伍下仍可能很长；首套合法结果、全部同分方案完成、全局最优证明是不同状态，不能用本报告的起点耗时替代后两者。
