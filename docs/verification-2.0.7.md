## 实现与兼容性

不可变候选和物理编队的完整负载分组保存，生产归档每个内容块最多 256 条、2 MiB，读取缓存只保留两个块。每条记录仍保留独立主键元数据，内容块与索引在同一个原子事务中写入；重复记录不生成新块。物理方案更新最近使用日期时，保持创建日期并更新元数据，复用原不可变负载。数据库名称与版本不变，现有单条记录和新内容块可共存，旧库无需一次性改写。

同一份规范化 JSON 文本复用于内容标识和记录校验，仍是原 SHA-256、原规范化规则、原条件标识与校验和。模型修订号保持 2，公式、最优排序、有效账号条件以及完整候选覆盖未变。没有引入账号专用方案库。

对外库列表仍是逐条逻辑记录。导出仍直接生成整个聚合库的一个未压缩 JSONL 文件，每条记录保留原 ID、内容、校验和及格式；不暴露内部块地址，不出现导出内容选择。新备份能按原格式迁移合并，旧单条备份继续导入。相同候选自动去重，已验证的冲突保留主记录和变体；缺少内容块会拒绝读取/导出，不生成缺项备份。

内容块写入配额失败的整批原子回滚、元数据插入失败的整批回滚、重复不增块、创建日期保留、物理方案调用、逐条备份、混合存储与冲突保留测试通过。当前计算的 OPFS 写缓冲仍为固定 256 KiB，编码区 1 MiB，传输块仍为 64 KiB；计算和后台任务不新增时长上限。沿用完成答案暂存、归档完整数/字节及校验核对后提升精确缓存的机制，候选块不会让部分归档提前成为完整答案。
