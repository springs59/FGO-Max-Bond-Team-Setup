# 关卡规则扩展：第一轮实现与剩余核验项

本分支以 PR #22 的约束提前检查修复为基础，扩展账号配队的规则支持。它是独立的开发分支，未合并 main、未发布，不能称为所有规则已完全支持。

## 已接入账号精确搜索的规则

| 类型 | 本轮实现 |
|---|---|
| `mySvtNum`、`svtNum` | 精确人数、上限、下限、区间、不等于；区分己方与全队，允许合法的纯 NPC/纯助战队伍 |
| `individuality` | 按身份/特性允许或禁止上场，可限定作用位置 |
| `supportOnly` | 仅助战出战，不再仅解释成“留一个助战位” |
| `fixedSupportPosition` | 指定允许的助战位置 |
| `fixedMySvtIndividualitySingle` | 己方只可使用指定身份/特性 |
| `fixedMySvtIndividualityPositionMain` | 必选己方前排身份/特性；有明确位置参数时纳入位置检查，源数据冲突另行阻止 |
| `mySvtOrNpc` | 指定位置由符合要求的己方或 NPC 满足 |
| `mySvtOrSupport` | 指定位置由符合要求的己方或助战满足 |
| `uniqueIndividuality` | 指定身份/特性不重复，联合检查己方与 NPC |
| `fixedCostume` | 阶段强制形象；使用实际形象的 COST、特性，临时可用且不改写账号解锁记录 |
| `activeGrandBoard` | 允许激活冠位的位置，枚举多个不同职阶己方冠位及其各自额外装备 |
| `fixedSvtIndividualityPositionMain` | 指定身份/特性必须在前排或禁止在前排 |

另接入阶段的多名固定/可选/替换 NPC、NPC 多件固定装备、无助战及系统助战策略、无限 COST 标记、NPC 未通关开放条件。未知限制仍明确拒绝，未验证的 NPC 解锁状态不当作已解锁。

上述 13 类是当前仓库关卡数据中出现的类型，不代表未来游戏版本可能增加的所有类型。特别是未知参数语义、遗漏的上游固定队伍信息，不能通过放开入口就视为支持。

## 防止再次长期无结果

新规则先形成约束域，再枚举合法物理队伍。固定位置和必选身份/特性会提前限制每个位置的候选；成员递归检查未满足的必选条件、身份容量、人数上限与下限；装备递归预留后续必选的礼装副本与最低 COST。已证明安全的普通效果使用向上放宽的得分界，活动效果保留精确末端结算。

外部 NPC 布局逐个生成，归档只保存 NPC 编号和位置，不在内存预先保留全部排列。当前精确搜索、全部合法同分配队、进度让出控制权、停止后已得结果、分页与导出继续保留。完整耗尽首轮字面枚举且无合法队伍的域直接复用无解证明，不重复构建等价签名；达到预算上限或找到见证的首轮不会被误当作无解。特殊约束下不展示未验证的可替换身份，也不套用旧普通队伍的复用结果。

实际页面查询补齐阶段脚本、完整元数据标记和 NPC 策略的传递。NPC 固定礼装全部参与结算和显示，并写入结果导出；多名前排 NPC 的前排分享加成按人数累加。全 NPC 队伍得到合法的零羁绊结果，不误报无解。

## 准备阶段优化

精确物理枚举直接从账号身份、形象和礼装库存建域，原先仍会重复构建旧求解器的系数索引。本轮移除这一步，仅影响 `scoreTeamPrepareOnly` 路径，旧求解器保留原有索引行为。

同一公开国服 447 个从者、2,504 张礼装目录、不使用 AI，在同一进程交替执行修改前后版本，各去掉一次预热，取 5 次中位数：

| 查询准备 | 修改前 | 修改后 | 中位准备耗时减少 |
|---|---:|---:|---:|
| 单 NPC 关卡 | 322.82 ms | 44.03 ms | 86.36% |
| 精确三人关卡 | 333.67 ms | 41.59 ms | 87.54% |

这是准备阶段的本机对比，不是完整最优搜索提速比例；测量时存在其他回归任务。原始记录见 `docs/quest-rule-preparation-benchmark.json`。

## 实际数据覆盖

使用当前仓库国服 831 条、日服 3,192 条，共 4,023 条关卡/阶段记录扫描全部限制类型。对其中 820 条需要扩展求解的记录，采用公开图鉴、合成全持有账号、无己方礼装、COST116，补充已通关先决条件，逐条检查首个合法结果：

| 项目 | 结果 |
|---|---:|
| 需要扩展路径的阶段记录 | 820 |
| 得到通过当前约束和精确结算的首套配队 | 814 |
| 位置元数据语义冲突，明确阻止 | 6 |
| 到观察上限仍没有结论 | 0 |
| 原先 804 条不支持记录中，本轮得到首套配队 | 798 |

本轮本机 814 个首套配队最多 14 个枚举节点，最长约 143 毫秒。它不是实体手机测速，不包括把全账号礼装全部加入后的复杂度，更不代表完整全局最优证明或所有同分队伍枚举的耗时。814 套见证通过的是当前已编译的约束与结算，不能替代逐关游戏内编成核验。

## 尚未解决的 6 条记录

日服 `94091512:1`、`94091515:3`、`94091516:1`、`94162313:1`、`94162316:3`、`94162317:1` 涉及相同组合：

- 必选己方宫本伊织的 `fixedMySvtIndividualityPositionMain` 带 `targetVals2=[1]`。
- 固定 NPC 的 `eventDeckIndex=1`。
- 提示文案只说明宫本伊织必须首发，没有明确解释两个位置参数的组合方式。

重新请求上游 Nice 数据后，该组参数仍然存在。例如 [Atlas JP 94091512 阶段 1](https://api.atlasacademy.io/nice/JP/quest/94091512/1)。目前不能确定这是“己方相对位置”、NPC 插入后的重排，还是其他参数语义。参考客户端的描述实现也不足以证明游戏实际排列。

因此对这组矛盾参数明确提示“位置参数语义尚待核验”，不返回可能非法的队伍，不把它报告成账号无解，也不将它计入已通过覆盖。**完成这 6 条的语义核验前，仍不能宣称所有规则已完整支持。**

## 验证

- `src/solver/quest-party-constraints.test.js`：96 组小规模独立占位/装备检查，2,043 套物理队伍；覆盖人数比较、身份/特性、相对支持来源、多个同时 NPC、可选多 NPC、纯助战、强制形象与账号不被改写、多冠位共享库存。双冠位两张礼装的全部 54 种合法普通/免费槽装配一致；混合满破/未满破副本的 376 种装配也逐一一致且无重复。
- `scripts/check-extended-quest-rules.mjs`：4,023 条元数据扫描、820 条扩展路径首套见证与上述 6 条显式阻止检查；已加入 CI。它使用有上限的探查，不以超时冒充无解。
- 1,000 组随机独立普通/特殊效果穷举仍保留全部 232,234 套同分队伍；原七职阶冠位 196 组起点检查仍通过。
- 实际 Chromium 页面/Worker 验证两个 NPC、两件系统固定礼装、阶段无限 COST 覆盖、移动宽度显示、分页/导出及原有停止保留回归。固定 NPC 礼装不扣己方 COST；B100、己方 1 号位、NPC 在 2/3 号位及 10%/20% 固定礼装的用例得到 166，与独立算式一致。

本轮未训练或替换 AI 模型。新增规则路径先使用约束传播和当前精确枚举；它的完整查询速度仍需进一步压力验证，不能用“首套快”替代“最优证明快”。
