# 关卡规则扩展与副本出战要求

本分支以 PR #22 的约束提前检查修复为基础，扩展账号配队的规则支持。随 2.1.9 发布。当前仓库全部 14 种规则已接入，未来类型与未见参数仍须核验。

## 已接入账号精确搜索的规则

| 类型 | 本轮实现 |
|---|---|
| `mySvtNum`、`svtNum` | 精确人数、上限、下限、区间、不等于；区分己方与全队，允许合法的纯 NPC/纯助战队伍 |
| `individuality` | 按身份/特性允许或禁止上场，可限定作用位置 |
| `supportOnly` | 仅助战出战，不再仅解释成“留一个助战位” |
| `fixedSupportPosition` | 指定允许的助战位置 |
| `fixedMySvtIndividualitySingle` | 己方只可使用指定身份/特性 |
| `fixedMySvtIndividualityPositionMain` | 副本必选己方首发身份/特性，可用 1–3 号位；与 NPC 绝对席位、用户手动钉位分开 |
| `mySvtOrNpc` | 指定位置由符合要求的己方或 NPC 满足 |
| `mySvtOrSupport` | 指定位置由符合要求的己方或助战满足 |
| `uniqueIndividuality` | 指定身份/特性不重复，联合检查己方与 NPC |
| `fixedCostume` | 阶段强制形象；使用实际形象的 COST、特性，临时可用且不改写账号解锁记录 |
| `myGrandSvt` | 当前空附加参数、equal 类型要求 1 名符合身份/特性的己方冠位；重复提示不当作 2 人，账号必须实际选定冠位，助战不能替代 |
| `activeGrandBoard` | 允许激活冠位的位置，枚举多个不同职阶己方冠位及其各自额外装备 |
| `fixedSvtIndividualityPositionMain` | 指定身份/特性必须在前排或禁止在前排 |

另接入阶段的多名固定/可选/替换 NPC、NPC 多件固定装备、无助战及系统助战策略、无限 COST 标记、NPC 未通关开放条件。未知限制仍明确拒绝，未验证的 NPC 解锁状态不当作已解锁。

上述 14 类是当前仓库关卡数据中出现的类型，不代表未来游戏版本可能增加的所有类型。特别是未知参数语义、遗漏的上游固定队伍信息，不能通过放开入口就视为支持。

main 的 2026-10-23 自动更新新收录 9 个阶段，并带来 `myGrandSvt` 类型（8 个阶段、16 条重复提示规则）。发布前的完整规则检查发现并阻止了遗漏。按阶段原始提示实现恰好 1 名符合 Extra 特性的己方冠位，重复规则去重；账号未选定冠位时不能把普通从者当作冠位。独立检查覆盖双候选冠位分别选择、仅一名已选定、无已选定冠位与未知参数拒绝。其他未见参数不猜测。原始数据见 [JP 94163702 阶段 1](https://api.atlasacademy.io/nice/JP/quest/94163702/1)，活动说明见[官方冠位名代战公告](https://news.fate-go.jp/2026/10/grand_substitute/)。

## 防止再次长期无结果

新规则先形成约束域，再枚举合法物理队伍。固定位置和必选身份/特性会提前限制每个位置的候选；成员递归检查未满足的必选条件、身份容量、人数上限与下限；装备递归预留后续必选的礼装副本与最低 COST。已证明安全的普通效果使用向上放宽的得分界，活动效果保留精确末端结算。

外部 NPC 布局逐个生成，归档只保存 NPC 编号和位置，不在内存预先保留全部排列。当前精确搜索、全部合法同分配队、进度让出控制权、停止后已得结果、分页与导出继续保留。完整耗尽首轮字面枚举且无合法队伍的域直接复用无解证明，不重复构建等价签名；达到预算上限或找到见证的首轮不会被误当作无解。特殊约束下不展示未验证的可替换身份，也不套用旧普通队伍的复用结果。

实际页面查询补齐阶段脚本、完整元数据标记和 NPC 策略的传递。NPC 固定礼装全部参与结算和显示，并写入结果导出；多名前排 NPC 的前排分享加成按人数累加。全 NPC 队伍得到合法的零羁绊结果，不误报无解。

## 准备阶段优化

精确物理枚举直接从账号身份、形象和礼装库存建域，原先仍会重复构建旧求解器的系数索引。本轮移除这一步，仅影响 `scoreTeamPrepareOnly` 路径，旧求解器保留原有索引行为。

同一公开国服 447 个从者、2,504 张礼装目录、不使用 AI，在同一进程交替执行修改前后版本，各去掉一次预热，取 5 次中位数：

| 查询准备 | 修改前 | 修改后 | 中位准备耗时减少 |
|---|---:|---:|---:|
| 单 NPC 关卡 | 322.82 ms | 44.03 ms | 86.36% |
| 精确三人关卡 | 333.67 ms | 41.59 ms | 87.54% |

这是准备阶段的本机对比，不是完整最优搜索提速比例；测量时存在其他回归任务。原始记录见 `docs/quest-rule-preparation-benchmark.json`。

## 区分固定席位、必选出战与用户钉位

规则从当前关卡阶段的结构化元数据生成，不按关卡名字猜测、不在运行时代码写死某位从者或这六个关卡 ID，不写入用户的 `slotPins`。

| 要求 | 搜索时如何处理 |
|---|---|
| 阶段 NPC 的 `script.eventDeckIndex` | NPC 占用指定绝对席位，不能被己方成员覆盖 |
| `fixedMySvtIndividualityPositionMain` | 必须用己方符合身份/特性的首发成员；在空闲的 1–3 号位搜索，NPC 同身份也不能替代“己方” |
| 用户手动钉某位从者到具体号位 | 仍是精确位置条件；与副本条件联合验证，放后排不能满足必选首发 |
| 没有副本要求的成员与位置 | 在其他人数、库存、COST 等条件内自由搜索 |
| 切换副本或阶段 | 重新读取该阶段规则；不把上一阶段的必选成员变成长期手动钉位 |

此前阻止的日服 `94091512:1`、`94091515:3`、`94091516:1`、`94162313:1`、`94162316:3`、`94162317:1`，都是把必选首发类型的 `targetVals2=[1]` 当成绝对 1 号位，才与固定 NPC 冲突。重新读取 [Atlas JP 94091512 阶段 1](https://api.atlasacademy.io/nice/JP/quest/94091512/1) 后，游戏自身的 `dialogMessage` 与 `noticeMessage` 都要求宫本伊织设置为“スターティングメンバー”（首发成员），没有要求绝对 1 号位。NPC 大和武尊的脚本则明确指定绝对 1 号位。

修正后分别处理：大和武尊占 1 号位，己方宫本伊织可在 2 或 3 号位；己方最多 5 人，其他位置继续搜索。宫本伊织是该副本确实点名的成员，不能删除这个要求，也不能延续到其他副本。

`targetVals2` 并没有跨类型统一的“绝对席位”语义。本轮按上述必选首发类型及游戏提示实现当前数据出现的空参数、`[1]`、`[1,2,3]`；没有宣称已还原该字段所有可能的底层含义。该类型出现其他参数时明确阻止猜测。真正指定席位的 NPC 脚本、`fixedSupportPosition`、其他位置型规则及用户钉位仍按各自规则处理。

页面“本次计算条件”分别列出副本固定出战、必选首发和人数要求，并说明只对当前阶段生效。页面查找已选副本时按“关卡 ID＋阶段”精确匹配，移除仅按 ID 回退到其他阶段的行为；浏览器回归验证同一副本下一阶段不再要求前一阶段的 NPC 和己方成员。

## 验证

- `src/solver/quest-party-constraints.test.js`：117 组小规模独立占位/装备检查，2,206 套物理队伍；覆盖人数比较、身份/特性、相对支持来源、多个同时 NPC、可选多 NPC、纯助战、强制形象与账号不被改写、多冠位共享库存。新增覆盖 NPC 固定在 1/2/3 号位、必选己方在剩余前排、手动钉后排不合法、NPC 不替代己方、换关卡不保留副本要求。双冠位两张礼装的全部 54 种合法普通/免费槽装配一致；混合满破/未满破副本的 376 种装配也逐一一致且无重复。
- `scripts/check-extended-quest-rules.mjs`：4,032 条元数据扫描、829 条扩展路径首套见证及固定 NPC / 必选己方首发的独立落位检查；已加入 CI。它使用有上限的探查，不以超时冒充无解。
- 1,000 组随机独立普通/特殊效果穷举仍保留全部 232,234 套同分队伍；原七职阶冠位 196 组起点检查仍通过。
- 实际 Chromium 页面/Worker 验证两个 NPC、两件系统固定礼装、阶段无限 COST 覆盖、移动宽度显示、分页/导出及原有停止保留回归。固定 NPC 礼装不扣己方 COST；B100、己方 1 号位、NPC 在 2/3 号位及 10%/20% 固定礼装的用例得到 166，与独立算式一致。

本轮未训练或替换 AI 模型。新增规则路径先使用约束传播和当前精确枚举；它的完整查询速度仍需进一步压力验证，不能用“首套快”替代“最优证明快”。
