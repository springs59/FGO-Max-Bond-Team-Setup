# 账号冠位信息与推荐边界（2.1.23）

> 后续纠正：2.1.24 按对应职阶/冠位栏判断冠位是否缺失，替代本页“账号有任意冠位”的判断。见 account-grand-2.1.24.md。

账号完整库存用于判断是否存在真实冠位，判断发生在职阶、特性、库存筛选与位置约束之外。账号已有任意冠位记录时仅允许这些身份成为冠位，不能用普通从者的假设冠位修补无解条件；账号区独立显示数量与完整名单。

| 条件 | 行为 |
| --- | --- |
| 已有合格冠位，未指定位置 | 搜索全部合法己方位置 |
| 已有冠位，但职阶、特性、筛选或固定位置排除它 | 不推荐新冠位；必须带冠位时无解，可选规则可保留普通编成 |
| 账号无冠位且关卡强制冠位 | 推荐当前持有的合规选择，标明先完成冠位选择 |
| 账号无冠位且关卡允许特殊冠位 | 同时考虑普通编成与符合规则的条件冠位编成 |
| 关卡不启用冠位规则 | 不凭空启用冠位特殊计算 |
| 自由配队 | 保留自由图鉴搜索规则，不受已导入账号限制 |

导入解析未发生丢失：本地复核此前提供的登录回包识别到 7 名真实冠位。回包及账号内容不进入仓库或发布产物。合成回归覆盖回包解析、账号保存和切换后恢复、筛选后空候选、已有冠位特性不符、可选与强制规则、Worker 说明及页面名单。此前 JSON/JSONL 条件提示和后排冠位浏览回归继续保留。

边界：这里验证的是此前提供的回包与合成条件；未直接读取用户当前已安装程序的本机存储，也不声称长时运行验证。没有修改账号真实身份或历史记录。更新账号仍需导入最新回包。

## 本地验证结果

- 完整 `npm test`、9 项安装包版本测试通过。
- 16 组冠位策略、34 组全位置搜索回归通过。
- 13 组原有浏览器检查及 8 类冠位页面检查通过，覆盖导出、档案、后排、已有冠位被排除和响应式页面。
- 真实回包经页面导入识别 7 名冠位，名单完整显示，刷新后保留。
- 196 组冠位首队、384 组关卡可行性、CN/JP 共 4032 阶段规则解析及 829 个特殊阶段首队检查通过。后三者验证首套合法队伍/规则支持，不代表全目录最高分证明。
- 发布后还需以 Windows 安装升级、Android 模拟器与签名流水线结果作为原生验证。
