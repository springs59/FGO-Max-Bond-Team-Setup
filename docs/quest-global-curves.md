# Anonymous effect curves and quest feasibility

The review now starts from anonymous effect distributions, not a fixed party.
A curve states how many anonymous recipients receive each number of conditional
20%/10% hits, each unrestricted percentage, the portrait flat addition, support
contributions, and front/back first multipliers. The party witness is collapsed
under “one realization in current data” and is not an input to the default solve.

There are two explicit domains. The theoretical domain assigns conditional CEs
to arbitrary subsets of anonymous recipients, within regional CE quantities,
party size, normal-slot counts, reward slots, support loadouts and a CE COST
budget. It does not assert that real target traits can all coexist. By default,
servant COST reserve is zero: only CE COST is constrained in this domain. The
reserve can be changed. The current-data domain applies actual identity/form,
class, trait, CE scope, NPC, costume, slot and cost constraints before optimization.
Its COST always includes the real own servants. Selecting servant IDs reprojects
complete source data and solves again; it never filters the old witness party.

For each equipment composition, hit-count vectors are enumerated independently
for own conditional rates and each support conditional CE. Equal recipients are
multisets within front and back bands. The distributions cover every independent
binary-target hypothesis: a recipient with h hits can be marked in any h of the
selected same-rate CE columns. Permuting those columns cannot change the anonymous
effect and is merged. Different types' joint distributions are retained.

All-hit distributions dominate partial-hit distributions at identical slot counts,
COST and other bonuses. The theoretical envelope therefore compresses them with a
proof, while the full-results generator retains partial hits. It streams all
configurations and all distributions, 30 per page, without a top-N cutoff. The
five-own/five-conditional-20 plus one conditional-20 support example has 28,392
front/back joint distributions when distinguishing own and support hits. The
supplied examples (five recipients hit six; four hit six and one hits five/four)
are available as a direct comparison.

The current-data snapshot is 2026-10-10 04:37:41 UTC. Rule families include regular,
Grand templates and active activity quests, plus the 120 previously excluded
special phases. NPC effective traits come from Nice detail.traits, not the empty
follower override array. Raw phase scripts provide forced costumes. External
members occupy actual physical seats and keep fixed equipment. Each front external
member adds 4% to the first multiplier; NPCs do not themselves receive own-party
bond. Support-only phases produce a zero function.

Each own normal CE consumes one own member's normal slot. Each enabled, eligible
own Grand has one free reward slot, with regional/quest class and physical-position
limits. Basic classes allow one selected Grand per class; Extra permits two in
aggregate. Multiple external characters carry their actual equipment independently.
The separate ten-bond CE slot adds no quest bond; NP50 is not a bond bonus. Empty
normal/reward slots and portrait count zero are included.

Native envelope generation may free the most expensive eligible selected CEs:
for fixed effects and eligible owners this weakly lowers COST. The browsing worker
retains other valid assignments. The native front/back DP preserves the Grand
class presence needed by reward eligibility; it can discard irrelevant class
multiplicity in capped carriers without changing available reward counts. Unknown
position patterns fall back to the exact role DP.

Activity curves show anonymous affected member counts, self/campaign percentages,
party provision and sources. The optional realization names the actual identities.
The CE-only theoretical panel intentionally excludes activity self bonuses; the
current-data layer evaluates effective activity sources rather than assuming all
anonymous recipients qualify for an event bonus.

Integer arithmetic uses the two separate floors. Exact residue envelopes cover
all nonnegative integer base values; graphs and grouped intervals display 0–6000
by default. Display identity is the anonymous effect, slot composition, support
content and COST, not own servant name. Identical content combines adjacent and
overlapping intervals; separated intervals share one expandable item.

Run prepare.mjs, then prepare-special.mjs with the downloaded Nice/Raw phase cache.
Compile global.cpp into the work directory's quest-global-engine and run
precompute.mjs. Validate with verify.mjs; then build-review.mjs and
check-review-ui.mjs. The native records contain concrete feasibility witnesses,
while anonymous-effects.js is the independent theoretical effect generator.
Literal tests cover anonymous binary hits, mixed universal/portrait equipment,
COST, floors, physical NPC seats, mandatory front roles, costumes, multiple reward
owners, duplicate basic classes and the aggregate Extra limit. UI checks execute
real worker threads in a DOM fixture, including theoretical examples, paging,
servant reprojection and pinned support. They are not real-browser visual QA.

The review contains theoretical precomputation for every rule scene. Actual-data
banks can be absent for unusually expensive scenes: these are explicitly marked,
have no fabricated actual envelope, and keep their full source for exact on-demand
solving and result browsing. The manifest separately counts theoretical scenes,
actual precomputed scenes and deferred actual phases. A stopped solve leaves the
theoretical result intact. Selecting identities still reprojects full source.

For theoretical reward positions, capped front/rear placement is enumerated too:
a rear capped carrier may enable a rear-only Grand reward slot. Arbitrary hits on
capped members do not affect the function and are treated as one equivalence class.
Each theoretical legend states owned CE types/counts, helper CE effects and joint
recipient hit counts. Full-results browsing respects the current helper/layout
filters. Run scripts/effect-curves/precompute.mjs before building the review.

For the native multi-Grand DP, equipped minus available normal seats is a necessary
minimum reward count. A basic class can provide at most one reward carrier and
Extra at most two. This supplies exact class occupancy and remaining-seat bounds;
it does not cap candidate counts or sample identities. The multi-Grand literal
fixtures also test distinct basic classes, extra equipment and four own members.
precompute-multi.mjs splits independent support branches and merges their complete
frontiers; FRONT_CACHE_LIMIT controls memory use, without changing results.

The default portrait cap is ten, including zero-count choices; physical normal
and reward slots remain the binding equipment limit. Envelope construction keeps
the best intercept for each equal slope in each exact residue before allocating
line objects, which preserves the envelope while bounding temporary memory.
finalize-review.mjs refreshes code in an existing large HTML with Buffer slices,
exports anonymous Chinese CSV descriptions and updates the artifact checksum.
The 2026-10-11 review has 130 theoretical scenes, 128 actual banks and two actual
scenes explicitly deferred to exact on-demand solving. check-review-ui.mjs also
checks stale asynchronous scene loads, invalid reserve clearing and deferred
solve completion/cancellation; its completion fixture is not evidence that the
two large real scenes were precomputed.
