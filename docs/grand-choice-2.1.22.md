# 2.1.22：无冠位推荐与全部前序修复

用户要求的完整改动一并发布：未指定冠位位置搜索全部合法己方位置；恢复方案库入口、明确存入和当前条件重验；保留导出格式；缓存命中本次节点为零；区分最高分证明与同分补全。

## 冠位选择策略

- 必须带冠位时，优先使用账号已有、符合本阶段范围的冠位。
- 缺少符合范围的冠位时，从当前持有、可用形态中推荐合规选择，继续校验职阶/特性、人数、站位、锁定、COST 与礼装库存。
- 非必选但冠位效果启用时，同时考虑不使用冠位以及按启用位置、同职阶冠位数量约束使用冠位的方案；缺少可用冠位时，条件方案明确标注需先选择冠位。
- 没有启用冠位规则的普通编成不会凭空获得冠位额外礼装槽。
- 明确关卡位置限制继续生效；未指定位置不默认限前排。没有合格候选或锁定冲突时仍无解。
- 不改写账号 `isGrand`，不改写固定位置。候选标记随实际所选从者生成，界面、JSON/HTML/PDF/Word 队伍报告和完整 JSONL 档案均保存使用前提。
- 修复前端联动：特殊冠位规则不依赖“冠位战”分类；应用结果后保留求解器选定的冠位与后排位置，避免渲染时清除标记、误判条件改变并丢失队伍。
- 最高分证明的范围是当前实际/推荐冠位选择条件；包含推荐的搜索在进度中明确说明。可选冠位场景中的普通队伍仍保留实际资格。
