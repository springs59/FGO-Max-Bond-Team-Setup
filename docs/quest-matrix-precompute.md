# 预计算方案库与本地临时缓存

软件继续使用现有 2.0 求解器。推荐、固定队伍礼装曲线及编队效果／精确核实的本地计算只写临时磁盘日志，不在计算期间逐条写入永久方案库。缓冲上限为 256 KiB，编码暂存区为 1 MiB；周期性刷盘，完成时封存。计算结束、主动终止或进程异常退出后，已刷盘的完整记录保留。

结果页提供内嵌的“是，保存到方案库”“否，删除临时文件”，不另弹确认窗口。启动或打开方案库不会自动导入遗留日志。选择保存才以有界批次合并候选和物理编队；完整答案必须核对日志记录数、字节数、校验和与完成证明。终止搜索仅能保存实际观察到的候选，不能生成最大值证明。选择删除仅删除对应临时日志及暂存答案，不删除已有方案。保存失败保留文件，已提交的前缀可安全重复合并。

日志用于控制保存阶段的内存与提供恢复，并不能保证阻止所有进程崩溃。异常终止可能丢失尚未刷盘的最后一个周期；不能把缺失部分标为已完成。

## 仓库计算范围

`scripts/quest-matrix-plan.mjs` 从国服、日服独立快照生成计划：

- 0～5 星、快照中的各职阶和 Extra、五种属性、14 个筛选特性的单值笛卡尔积。
- 无限制、单轴对照，以及少量多星级、多职阶、多属性、多特性的 OR／AND 组合。
- 自由关卡的高、低基础羁绊，两个不同修炼场，宝物库，以及快照中符合编成支持条件的活动／其他关卡。
- 当前批次固定自由图鉴、COST 95、无茶壶。账号、其他预算和钉选条件仍由软件按实际输入重新核算；已保存的物理方案可作为候选。

每区服 7,676 个筛选表达式。空集合不虚构候选；相同身份和形态集合复用一次完整求解。关卡仅在基础羁绊、编成规则和每个从者的有效加成均一致时共享求解结果，再分别写入完整条件的查询键。当前计划共 8,226 个独立任务；实际完成量以 `generated/quest-matrix/index.json` 为准。

关卡日期来自源快照，未知日期和历史关卡不代表当前开放。方案库保留实际计算结果与非最优候选，不额外枚举被剪枝的状态。查询键保守地包含输入，数据、账号或条件不同时不会冒充精确命中。软件调用公共物理方案时重新检查身份、形态、筛选、库存、位置和 COST。

## 生成、校验与发布

当前生成入口已暂停：先发布账号曲线与队伍对比等功能，用户验证并明确允许后才恢复。下列命令保留用于后续流程；暂停期间生成命令会在计算前退出。未来批次须重新规划所有支持的 COST。

```sh
npm ci
node scripts/precompute-quest-matrix.mjs
node scripts/verify-quest-matrix.mjs
python3 scripts/pack-quest-matrix.py /absolute/path/to/publish-batch
```

`MATRIX_JOBS` 可控制单次批次任务数，不限制单个求解器的搜索时间。完成任务后原子更新清单；磁盘候选流完整读回，并逐条检验曲线在七个基数下的两次取整，获胜方案用独立公式和 COST 核验。校验脚本另检查生产导入格式、校验和、实际筛选及查询键，并抽样通过生产导入和精确读取接口。

工作数据库位于执行器临时目录，公开归档与原子清单是跨环境恢复来源；缺少工作数据库时从归档重建，继续跳过完成任务。发布压缩块只改变分组，不删去任何结果。下载清单绑定 Git 提交、大小和 SHA-256，逐块校验并合并；已合并块不重复下载。

预计算下载是用户主动选择的操作。安装资源生成和 Pages 资源打包排除整个 `generated/quest-matrix`。构建命令不启动上述批量仿真。代码及数据先发布在 `precompute/quest-condition-matrix` 分支，下载 feed 指向该分支已完成的资源提交，避免分支更新期间混用不同版本。

自动推荐在仓库导入或账号更新后，分批匹配并保存每个账号独立的可用物理编队配置。计算时按当前筛选生成精确曲线，只送入相关最优及次优代表，再完整核实当前条件；曲线允许缺口，不做虚构插值。候选输入预算不限制实际观察记录、存储或完整导出。大型方案库按页汇总与导出，导入使用有界暂存批次；检索公共编队先检查成员和筛选，避免把整个方案库搬进计算进程。下载数据压缩后仍可能很大，导入需要数 GB 本机存储。
