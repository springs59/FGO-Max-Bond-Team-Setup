# 国服与日服数据边界

| 内容 | 处理方式 |
| --- | --- |
| 羁绊取整、配队算法、布局、外号与显示名称映射 | 共用规则；映射不会增加未实装对象 |
| 从者与礼装实装清单 | 分别从 Atlas CN、JP 完整导出构建 |
| 同 ID 从者的灵基、星级、职阶、COST、特性、技能和强化 | 使用对应区服原始字段，日服不会以国服同 ID 字段覆盖 |
| 礼装数值、技能与可用范围 | 使用对应区服 nice_equip |
| 活动、加成、关卡、开放时间和重复规则 | 按区服构建；以各服 raw quest friendshipExp 核对基础羁绊 |
| 导入账号、钉选与练绊偏好、最近关卡 | 浏览器按区服保存，切服恢复对应设置 |
| 推荐结果与离线求解索引 | 缓存键含区服与数据版本；现有国服预计算不在日服使用 |

国服继续使用 src/data 下的 CN 文件和 generated 下的 CN 索引。日服使用 src/data/jp/bundle.json，内含独立 version、servants、ces、traits、quests、bondBonuses 和 questBrowserIndex；metadata.json 记录数量与刷新状态。旧 jp-extra-* 文件只为旧工具兼容保留，页面不再用它们合并国服图鉴。

日服快照从 JP basic_war 发现每日和冠位章节，保留实际关卡，不注入国服合成的冠位目录。含零羁绊的剧情在查询 raw friendshipExp 后排除，避免把玩家 EXP 误当羁绊。普通关卡已验证的羁绊可从上一份 JP 快照复用，活动关卡重新读取。

切服时停止旧推荐，清除旧队伍、详情与关卡，再载入所选区服。没有该区服有效快照时显示载入错误并阻止推荐，不回退到另一服。首次 JP 快照缺失会阻止快照流水线提交；之后 JP 更新失败仅保留此前通过校验的 JP 数据。快照刷新不会自动提供账号的剧情解锁状态。

验证：npm test 包含跨服同 ID 字段、未实装对象、活动窗口、账号库存和缓存隔离，以及仅访问 JP 的快照模拟测试；node scripts/validate-regions.mjs 校验真实 JP 发布文件。

2026-10-06 发布验证：CN 445 名从者、2480 张礼装；JP 470 名从者、2706 张礼装、4009 个含羁绊关卡。JP 清单中有 25 名从者、237 张礼装不在 CN；排除名称翻译后，56 个共有从者 ID 的灵基数值/特性或技能版本字段存在差异。

真实 JP 离线图鉴的普通自由配队和模拟全库存账号配队（COST 116）均通过完整结算校验，Node Actions 环境分别约 1.60 秒、2.49 秒，均返回 search-complete。验证使用与网页相同的快速求解路径，强制传入国服旧索引以检查隔离；单独子进程设置 30 秒超时。耗时不代表特定手机、真实账号或复杂钉选情景的承诺。
