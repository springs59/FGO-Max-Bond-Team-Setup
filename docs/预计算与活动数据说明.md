# 预计算与活动数据

## 数据来源与发布

- 每六小时由 `snapshot-game-data.yml` 拉取国服与日服数据。关卡列表来自 Atlas basic phase search；每个关卡的基础羁绊重新读取 raw quest phase 的 `mstQuestPhase.friendshipExp`，不能使用 basic search 的 `bond`（该接口当前返回玩家经验）。无法核对字段时停止发布。
- 数据、求解索引与预计算结果经过校验后才提交。内容相同时保留原文件，只更新 `generated/data-status.json` 的检查时间。
- 活动从者的加成、关卡加成和生效区间来自 `src/data/bond-bonuses.json`。页面按当前时间再次判定；跨越生效或过期边界时使旧结果失效。

## Action 提前计算的内容

1. 从者全部形态、COST、属性与特质；礼装及其条件命中表；关卡索引。
2. 当前开放的活动关卡与从者之间的实际加成矩阵，以及礼装条件命中与各形态数据。索引保存加成率、固定加成及作用对象，不把任一副本的最终羁绊当作通用常数。页面用所选关卡的 `bond` 作基数，按前排、第二层加成、固定加成和取整规则逐位置结算；数据版本或活动状态不一致时回退动态计算。
3. 无特殊加成的修炼场极级和宝物库极级的默认自由配队方案。修炼场的敌方职阶不限制己方从者，七种同羁绊基数的关卡共用一次完整搜索；索引为每个关卡保留独立映射。

默认方案只是少数精确匹配查询的快捷缓存；浏览器仍重新结算队伍分数。羁绊基数改变会影响取整与固定加成的排序，不能无条件把某个基数下的最佳队伍认定为另一基数的最佳队伍。活动状态变化、关卡过期或数据版本不匹配时回退实时求解。每个关卡的前若干方案不能证明任意账号、COST 上限、指定前排或礼装限制下的最优解，因此这些条件仍由浏览器在预构建的从者、形态、礼装与活动加成索引上完成搜索。完整账号活动搜索的性能瓶颈尚未消除，不能把默认方案称作“全部账号的完整预计算”。

活动搜索的上界剪枝会计入每名从者自身加成、已选从者的全队加成，以及尚可上场的不同从者所能提供的最大全队加成。这样可以安全排除不可能超过当前方案的分支；它仍需搜索账号所有权、COST 和锁定条件所决定的组合，不能保证大账号即时返回。

## 验证

- `npm test` 覆盖源字段缺失时拒绝发布、活动关卡命中与跨关卡隔离、活动状态变化后回退、索引还原队伍的总羁绊结算。
- `node scripts/validate-data.mjs` 要求快照明确标记羁绊来源，并验证关卡羁绊字段。
- Action 中任一索引构建或测试失败，均不提交候选快照。
