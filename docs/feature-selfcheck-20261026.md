# 功能自检与发布前检查（2026-10-26）

后续更新：本文记录修复前自检。无冠位推荐缺口及特殊关卡前端清除冠位标记的问题已由 2.1.22 修复，规则与新增验证见 [grand-choice-2.1.22.md](grand-choice-2.1.22.md)。原生内存及长时运行的边界仍需保留。

## 结论

本次完成完整自动测试、额外求解矩阵、13 组真实浏览器功能检查，以及原生更新/数据/文件保存逻辑检查。发现并修复了多个问题，但**不能认定所有功能全部正常**：无冠位账号的特殊编成自动推荐仍有缺口；Windows、Android 真实设备运行未验证。因此建议先补齐该推荐缺口，再决定合并与发布。

基础版本是 main `a2b21a36e980c157eae004263b8799dc4f1e6b5d`；取消默认前排冠位限制的本地提交是 `c5e3062c598f09e4ad10d4041c3d1827cd2ed99f`。本次没有上传、合并 main 或触发发布。

## 自检中修复的内容

1. 保留前一轮冠位修复：未指定位置时搜索全部合法己方位置；特殊编成也不额外添加默认前排限制。关卡明确限制继续生效。
2. `reuseOnly` 与 `createReuseEvaluator` 原先未正确接回求解器，手动调用可能重新搜索或始终匹配为空。现在只逐队重验并按当前条件重新结算，拒绝未持有身份、重复身份、不可用形态、库存/满破不足、COST 和锁定冲突；不复用旧账号分数或旧最优证明。
3. 页面改版遗漏的方案库入口恢复；当前队伍、当前推荐和对比队伍均可明确存入。普通计算不会自动写入方案库。库内结果以候选显示；不会继承上一轮计算的完整性证明。
4. 导出格式同时监听输入与变更事件，并优先使用保存的选择，避免页面重新渲染后选 JSON 却导出 HTML。
5. 完整结果缓存命中时不再把上一轮搜索节点计作本次搜索工作。
6. 压力报告允许“已证明最高分，但同分尚未补全”的未完成状态；仍拒绝超时却标记全部完成、最高分互相矛盾和不同输出单位的错误比较。
7. 修正过时自检：旧日志/缓存字段、跨账号缓存假设与当前协议保持一致；任务界面测试的 CSP 绕过只用于自动化注入，不改变产品 CSP。
8. 额外八个原先未接入 `npm test` 的既有测试，以及新增库重验、压力状态验证已纳入默认测试；CI 增加真实方案库入口/备份与 Worker 内存恢复检查。

## 尚未通过的功能

**没有冠位记录时，自动推荐冠位选择的路径仍不完整。**

用两名合成杀阶从者、COST 2、基础 100、无助战且账号均未标冠位检查：

| 条件 | 当前行为 | 判断 |
|---|---|---|
| 普通冠位计算 | 能选择一名从者作为冠位并给出队伍 | 已有自动选择；还缺明确“升冠后才能使用”的结果区分 |
| 同条件只增加“己方至少一人” | 特殊编成路径直接无队伍 | 不通过；这条人数条件本不应排除上述候选 |
| 关卡明确要求真实己方冠位 | 无真实冠位时没有当前可出战队伍 | 资格判断正确；单独的“推荐升冠后的队伍”流程尚未补齐 |

本次没有将普通从者偷偷改为账号真实冠位，也没有把升冠假设伪装成实际可出战资格。此缺口不能用其他全持有/全冠位矩阵通过来掩盖。

另一个已有边界：特殊 NPC/多冠位等扩展编成的旧物理方案库调用仍要求按当前关卡重新求解，尚未支持直接库内重验；队伍档案可离线查看。

## 验证边界

- 测试使用公开图鉴和合成账号，没有重建用户本次具体抓包及全部条件。
- 未重新进行真实 2 小时或 3 小时持续运行；日志生命周期中的多小时为模拟时间，压力报告框架用的是短截止时间。
- 原生数据模拟在默认约 2 GiB Node 堆限制下出现内存不足，使用 `--max-old-space-size=6144` 后通过。此数值是堆上限，不等于实际占用 6 GiB；也不能据此认定低内存手机已安全。
- Windows EXE 和 Android APK 没有构建或真机运行这份候选代码。已发布安装包检查验证的是解析器参考行为，不能冒充候选安装包验收。
- 最终浏览器检查使用 Playwright 1.62.1 和 Chromium Headless Shell 134.0.6998.35；未验证当前所有浏览器/WebView 版本。第三方远程立绘服务不作为算法验收前提。
- 代码只保存在本地修复分支；尚未合并 main，也未发布 Pages/EXE/APK。

机器可读记录见 `docs/test-results/2026-10-26-feature-selfcheck/summary.json`；原始可复现脚本见对应 `scripts/check-*.mjs` 与 `package.json`。
