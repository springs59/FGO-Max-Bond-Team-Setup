# 统一使用等效合并、框架起点和资源上界

本改动基于 PR #19 的合并版。历史版本在不同条件下的优势不能直接相加：代表解求解器返回一个结果，合并版还需保留全部最高分方案。统一目标和结算规则后，将能安全共享的数学判断放入同一搜索，而不是同时运行多个完整旧版求解器。

## 已组合的能力

| 能力 | 接入方式 |
|---|---|
| 等效从者、形态、礼装和站位合并 | 沿用可恢复方案组；替换池、共享库存和锁定条件不变 |
| 框架与 AI 高分起点 | 沿用已有框架起点和用户选择的三个模型；关闭 AI 时不调用模型 |
| 区间和分数剪枝 | 保留原有上界，以严格小于最高可行分数作为剪枝条件 |
| COST 与资源判断 | 新增对未来从者的价格松弛；对整队礼装收益同时约束槽位、实际剩余库存和预算 |
| 特殊规则精确结算 | 活动、冠位、固定 NPC、本人专属效果等不适用普通数学域的条件继续走原路径 |

新增资源判断仅在普通可证明域启用；全零常量域绕过它。原有上界已经能剪掉的分支，不再进行更贵的资源检查。没有把三个模型全部运行，也没有根据国服/日服标签硬编码一个“获胜模型”。当前结果不足以证明这样的自动选择对新账号仍然有效。

## 上界为什么安全

对固定队伍，把每件礼装对所有有效接收者的收益累加为一个整数向量，单位为千分之一羁绊。每件己方礼装只能从实际库存中使用，助战礼装从独立助战候选取上界。逐人向下取整的和不大于合计后向下取整，因此合计值可以安全作为上界。

剩余礼装收益同时取下列松弛问题的最小上界：

1. 按可用槽位数取最高收益，保留每种礼装的剩余数量。
2. 分数背包放宽槽位数，但保留 COST 和库存；分数部分向上取整。
3. 非负 COST 价格乘剩余预算，加上槽位内最高的非负“收益减价格乘 COST”。任何非负价格均给出上界，不使用模型预测作为剪枝依据。

从者阶段使用相同价格松弛；已选从者已经扣除 COST，未选身份和位置约束可以放宽但不能缩小可行域。所有整数乘积、和、排序交叉积都要处于安全整数范围；不能确认时跳过该资源上界。上界等于当前最高分时继续搜索，不因 COST 更高或副目标较低删除同分方案。

## 验证和复现

```sh
npm ci
npm test
npm run test:hybrid-bounds
FGO_SCORE_RANDOM_OUTPUT=test-output/hybrid/random.json node scripts/check-all-score-teams-random.mjs
npm run benchmark:hybrid-bounds
```

`scoreTeamAudit.resources:false` 仅用于审计对照：保持等效合并、AI 选择和原有上界一致，单独关闭本次资源判断。基准在同一进程交替运行开关两种状态，完整查询核对最高分、全部组数量和记录指纹，不能用少输出解释速度差异。

基准覆盖 15 种条件和四种 AI 选择；普通条件预热并测三轮，国服/日服开放条件默认各次仅运行两秒，明确标为未完成。本轮短测不能替代三小时证明，也不能据此宣称全面超过历史版本。

代码不改变数据更新、模型权重、用户 AI 选择、安装包版本或发布配置。结果和限制见 `docs/test-results/2026-10-22-hybrid-resource-bounds/README.md`。
