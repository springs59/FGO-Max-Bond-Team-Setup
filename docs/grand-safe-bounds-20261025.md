# Grand 与复杂关卡的精确搜索优化（2026-10-25）

查询继续证明全局最高分并收集全部并列队伍。AI 只调整访问顺序；上界、库存、COST 和关卡约束决定剪枝。没有引入候选数量截断，也没有调用旧求解器替代完整搜索。

## 改动

- 将安全分数上界扩展到 Grand、活动加成、固定 NPC、多件 NPC 礼装及特殊人数/冠位位置规则。普通礼装与奖励礼装按实际库存计算，免费奖励位不会因普通 COST 余量不足被错误排除；羁绊位继续不提供收益加成。
- 逐个去掉负加成来源后计算被动上界，避免负效果结束时低估收益。自身、条件和活动效果的最终得分仍使用原有精确结算；每层向下取整与大整数路径保留。
- 对确实等价的成员、形态和席位使用可逆分组。Grand 的礼装 ID、满破状态和额外位保留原始库存身份，展开时先扣除奖励/羁绊位占用的副本。
- 证明最高分时，合并等效的助战礼装候选，对不影响得分的普通礼装排列只证明一次，并省去未固定且没有收益的羁绊位选择。收集阶段保留原候选及全部可恢复的物理身份；等分分支不会被剪掉。
- 礼装效果表在一次查询的试探、证明和收集阶段复用。成员等价判断只比较不同的完整效果列，避免全图鉴中大量相同效果的重复比较。缓存随查询回收，不增加搜索节点日志或大型临时文件。
- Grand/复杂关卡接入所选模型的顺序建议。共享查询会话保持最多一次推理，关闭 AI 时为零；AI 预测不参与分数上界和合法性判断。低收益分支也定期交还控制，保留停止能力。

## 同机三轮短测

每个样本在独立 Node 进程中运行，AI 关闭，输入哈希一致。计时包括准备及核心搜索，不包括浏览器、Worker 调度、磁盘归档和界面。完整搜索预算为 2 秒；v2.1.12 与训练前样本取自同机未改动基线，最终代码重跑优化版。数值为三轮中位数，不能当作所有设备或所有账号的保证。

| 活动加成 | 462.8 ms | 53.4 ms | 5965，两版完整最高分一致 |

| 全图鉴 Grand | 2 秒未完成 | 2 秒未完成 | 同为暂定 42950，尚未证明 |

活动场景完整搜索约缩短 8.7 倍。条件 Grand 的旧版只有时限下界，因此不计算精确倍数。特殊人数场景证明最高分从 161.9 ms 缩短到 48.0 ms，其余时间用于收集并列队伍。

全图鉴普通查询达到本次暂定分数 7582 的时间从 1171.6 ms 缩短到 851.4 ms；首次预览约为 193.6/201.0 ms。全图鉴 Grand 三种场景达到各自同一暂定分数的时间约从 190.0/182.4/198.1 ms 缩短到 168.0/164.9/171.1 ms。这些是访问进展，不能代替完成时间或最优性证明；大规模礼装组合仍是后续瓶颈。

训练前 `6320a8ffd31c` 的接口只返回代表性推荐，不能代表全部物理同分结果。它在条件 Grand、活动、普通全图鉴的代表推荐中位数分别为 54.9/12.8/856.3 ms；普通全图鉴得分 7593 高于当前两版 2 秒时限内的暂定 7582，后者仍需继续搜索。三项真实 Grand 样本均触及历史接口的 6 秒进程时限，未取得有效完成时间。该基线不支持新增特殊人数域，因此跳过该项。不能据此声称优化版在所有场景已超过训练前版本。

原始样本、计分、证明状态、输入哈希与实现哈希见 [benchmark.json](test-results/2026-10-25-grand-safe-bounds/benchmark.json)。

## 正确性验证

新增测试使用独立的逐个物理候选构造与精确结算，核对压缩开关两种路径的最高分及全部结果集合：105 个 Grand 案例，27,168 套最优物理队伍；覆盖库存、满破、自身/条件/负效果、平加、免费高 COST 奖励位、助战奖励位、冠位席位、优先目标、满羁绊光环和逐层取整。分组目录经 JSON 往返后再展开，验证归档所需的身份与库存信息完整。

另有 8 个特殊规则案例对照关闭上界的完整搜索；3 个模型在两种关卡域中的 6 项检查均保持一次推理、同一最高分与全部物理并列结果，AI 关闭为零。1,000 组普通/活动/库存随机独立穷举对照保留全部 232,234 套最优物理队伍。完整 `npm test`、首个合法队伍压力矩阵及浏览器测试状态见同目录的 [validation.json](test-results/2026-10-25-grand-safe-bounds/validation.json)。

本机 Chromium 下载失败，浏览器部分以 PR 的 GitHub Actions 为准；本地 Node 测试不能替代真实 Worker、OPFS、分页、停止和导出验证。

## 复现

```sh
npm ci
npm test
node scripts/check-all-score-teams-random.mjs
node scripts/check-grand-score-pressure.mjs
node scripts/check-quest-score-feasibility.mjs
node scripts/check-extended-quest-rules.mjs

git worktree add --detach ../fgo-v2112 v2.1.12
git worktree add --detach ../fgo-v200 6320a8ffd31c
FGO_BOUNDS_BASELINE=../fgo-v2112/src/recommend.js FGO_BOUNDS_PRE_AI=../fgo-v200/src/recommend.js node scripts/benchmark-grand-safe-bounds.mjs
```

默认七场景、三轮、每次完整搜索 2 秒。`FGO_BOUNDS_CASES`、`FGO_BOUNDS_ROUNDS`、`FGO_BOUNDS_BUDGET` 和 `FGO_BOUNDS_OUTPUT` 可缩放测量；可选的 `FGO_BOUNDS_REUSE_BASELINE` 只复用相同输入哈希的未改动基线记录，优化版始终重新运行。
