# AI 初判 + 2.0.0 精确计算测试版

本分支以当前 main 的界面、数据、账号与原生功能为基础，将普通推荐的计算方式恢复到 `native-v2.0.0`（`6320a8ffd31c444fbc76a64e14e576f759e1de1c`），接入本地训练的小型神经网络排序模型。没有合入 main，没有启动全 COST 扩仓，也没有重新生成公共方案库。

## 回退范围

| 项目 | 当前处理 |

## 已训练模型

模型在本地运行，不调用聊天 API，不需要用户设备训练或联网推理。两套 16 隐层单元的小型网络分别给礼装效果组、从者效果组排序，模型与特征格式一起随代码分发。

固定随机种子生成 4,800 个训练查询和 800 个留出查询，其中有可行答案并参与监督训练/验证的查询分别为 3,732 和 641。样本来自人工构造的规则场景，以及当前公开国服图鉴的随机子集；不包含用户账号抓包。

教师为关闭 AI 的 2.0.0 礼装向量 DP。监督标签是已完成精算的答案中的礼装组使用比例、从者效果是否入选。同效果的任意身份/形态不作为互相矛盾的负标签。训练与留出按查询种子分开；图鉴实体可能重叠，因此这不是未见从者/未见活动泛化能力的完整验证。

训练报告：`docs/test-results/ai-200-training.json`。权重：`src/solver/ai-model.js`。可重现命令：

```sh
npm run train-search-ai
```

留出集不等标签对的排序准确率：礼装约 94.4%，从者约 76.1%。这是排序指标，不是配队正确率或提速倍数。数据规模和活动机制覆盖仍有限。

## 接入方式与正确性边界

- 普通 DP：模型给完整礼装效果组排序，并优先尝试预测的装备数量；每组的 0 至合法上限全部仍会尝试。剩余效果上界在排序后重新构造。
- 复杂搜索：模型重排完整从者效果组；原始组内的身份/形态不删除，排序后重新构造剩余候选后缀。
- 模型分数不进入羁绊结算、最终比较、数学上界或最优性声明。
- `aiMode: 'off'` 使用原搜索顺序；`'on'` 强制模型排序；默认 `'auto'` 在小效果域跳过推理。模型格式/数值无效时使用原顺序。
- 主练优先继续使用 2.0.0 的对应搜索路径，未新增主练剪枝。
- 不声称枚举了前 50 名所有身份组合。返回的是原核心产生的代表方案；数学等价的任意位与队伍对比功能保留。AI 遍历顺序改变后，附带返回的非最优候选数量可能不同。

## 临时文件与恢复

临时日志记录低频的阶段最好可行队伍，以及计算结束时返回的方案；不再保存普通推荐的全部礼装评分状态。每次检查点同步刷盘。终止任务后，可恢复已写入的检查点；没有写入磁盘的当前分支不能恢复，也没有实现从原搜索栈断点继续。

完成搜索的精确答案先进入待确认区，用户选择保存后才入库。中途终止的检查点只能作为候选。原有用户选择保存、删除、导出和导入流程保留，新检查点类型也可往返导入。

## 验证与复现

```sh
npm test
git worktree add --detach ../baseline-200 native-v2.0.0
FGO_AI_BASELINE="$PWD/../baseline-200" npm run verify-search-ai
```

`verify-search-ai` 对相同条件交替运行原始 2.0.0、关闭 AI、开启 AI、自动模式，检查目标分数与 COST 同分规则，并记录多轮耗时。原始基线来自独立 worktree，不能用当前代码的关闭 AI 分支代替它。

小规模另有独立无剪枝参考求解、所有助战效果/位置最优结果的对照；原有活动、形态、锁定空位、主练、库存和取整回归继续执行。有限样本一致性不能证明所有未来规则均无错误。

测试分支只供验证，不更新正式 Pages 或正式 Release。预计算审批文件继续保持暂停。

## 首轮性能结果

48 个独立查询、每个查询每种模式 3 轮，主目标与 COST 同分结果全部和独立原始 2.0.0 一致。对每个查询取中位数再相加：

| 模式 | 合计 | 查询中位数 | 查询 P95 |
|---|---:|---:|---:|
| 原始 2.0.0 | 3,982.6 ms | 7.10 ms | 613.49 ms |
| 本分支关闭 AI | 3,692.2 ms | 6.49 ms | 542.68 ms |
| 本分支强制 AI | 3,707.4 ms | 7.11 ms | 553.66 ms |
| 本分支自动模式 | 3,732.9 ms | 6.77 ms | 561.22 ms |

本轮模型相对同代码关闭 AI **没有证明整体提速**：强制开启合计约慢 0.4%，自动模式约慢 1.1%。部分查询节点减少，但部分增加；已有上界和 DP 状态处理仍占主要成本。原始基线与本分支的时间差也不能全部归因于模型。这里只测求解函数，未把有限小图鉴样本当作大型真实账号或 APK 端到端性能结论。详细条件、节点和耗时见 `docs/test-results/ai-200-performance.json`。

第一版完成了计算路径回退、实际训练、端侧接入和正确性对照；继续扩大训练或调整策略，应使用新的验证集，并以端到端收益为准。

GitHub Actions 独立环境再次通过同一组 48 查询对照。关闭 AI 合计 2,546.4 ms，强制开启 2,505.9 ms，约快 1.6%；自动模式约快 0.9%。结合本地约慢 0.4% 的结果，当前只能认为整体收益很小且依赖运行环境，尚未证明稳定加速。云端摘要见 `docs/test-results/ai-200-cloud-summary.json`。
