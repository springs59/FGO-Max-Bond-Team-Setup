# 冠位配队误判无解修复（2026-10-24）

基于 `c1a48623d326b5b7cb3548c7b622cc55694f220e`（v2.1.11 后的数据提交）。

## 已复现的问题

1. 同职阶有多个账号冠位时，完整配队搜索将它们全部放入必选名单。
   例如两个冠位均为 COST 1，固定其中一个在 1 号位，其余位置锁空，
   COST 上限 116，原版仍在 0 个搜索节点后返回无解。
   现在把冠位身份作为候选资格，仅在候选唯一时传播必选身份；
   多候选仍须由精确枚举选出合法冠位，用户明确的固定条件继续生效。
2. 自由配队或虚拟账号仍被残留账号的冠位身份限制。
   例如自由配队的账号对象只记录了不在当前候选中的冠位 ID 99，
   原版会把所有合法候选排除。现在仅真实账号模式使用账号冠位资格。
3. 关卡禁止助战时，自动冠位关联仍按原始“留助战位”设置排除 6 号位。
   例如固定账号冠位在 6 号位，关卡 `noSupport=true`，原始
   `allowSupport=true`，原版未能关联冠位并返回无解。
   现在 UI 与求解入口使用当前关卡的助战规则推导冠位位置。
