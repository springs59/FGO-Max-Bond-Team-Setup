# 活动羁绊加成资料

整理日期：2026-09-24（Atlas 国服 `nice/CN`、`export/CN/basic_event.json`）
用途：对照现有计算器实现，给后续「每次更新拉当前有效加成、过期不叠加」定解法。本文只整理事实，不改公式。

计算器里 `eventPassive` 已经能进第二层百分比，只加在该槽从者自己身上。推荐/求解目前恒为 0。

---

## 1. 两条线

|  | 线 A：给从者的加成 | 线 B：关卡活动、特定从者 |
| --- | --- | --- |
| 游戏表现 | 活动从者身上多一条被动（`XX力量 EX/A/B`） | 公告「某批从者在某关/全关卡牵绊 +20%/+30%」 |
| Atlas 对象 | 从者 `extraPassive[]` | 活动 `campaigns[]`，`target = questFriendship` |
| 典型幅度 | 自己 +50% / +20%；玛修全队 +5% | ×1.2（+20%）或 ×1.3（+30%） |
| 生效关卡 | 文案写「在『该活动』关卡通关时」 | `campaignQuests`：`questId=0` 为期间几乎全关卡；否则只加名单里的关 |
| 过期方式 | `extraPassive[0].startedAt/endedAt` 关掉，或留历史窗口 | 活动 `startedAt/endedAt` |
| 冠位研钻 | 文案指向活动关，默认不算 | `questId=0` 时算（巡灵祝祭、情人节关联、标题「特定从者 +20%」） |
| 现有代码 | 手选从者会拉 nice 并**把历史自身加成全部加总** | 完全没接 |

两条可以同时叠在同一名从者的第二层。活动礼装上的羁绊技能（技能 id `99xxxx`）是第三条，已经按 `func.eventId` 剔出礼装池。

标题同为「牵绊获得量提升」的日历活动，多数是羁绊提升**道具**倍率（`questUseFriendshipUpItem`），不是从者名单。

## 2. 现有代码怎么用

相关文件：

- `src/bond.js`：第二层读 `slot.eventPassive`
- `src/app.js`：下拉档位 `关 / +20% / +50%`；手选从者后写入求和结果
- `src/atlas.js` `passivesFromNice()`：扫 `extraPassive` 的 `servantFriendshipUp`
- `src/recommend.js`：推荐槽 `eventPassive: 0`
- `scripts/snapshot-game-data.mjs`：日更图鉴，不拉 `extraPassive`，也不拉 event campaign
- `src/data/skills.json`：空数组 `[]`

`passivesFromNice` 行为：

1. 跳过技能 `970663`（梦火的引导，15 绊光环另算）
2. 只收 `funcType === servantFriendshipUp`
3. `rate = RateCount / 1000`
4. 带出 `eventId`、`target`（`self` / `ptFull`）
5. 不读 `skill.extraPassive[0].startedAt/endedAt`
6. 不按当前关卡的 eventId 过滤

手选从者（`src/app.js`）：丢掉 `ptFull` 后对 `rate` **求和**。过期夏活 +20%、过期 +50%、主线关 +100% 会叠在一起。下拉只有 0 / 0.2 / 0.5，自动填的小数可以对不上。

推荐/求解：槽位创建就是 0；套用推荐计划只补立绘，不写活动被动。

需求原文（`.monkeycode/specs/2026-09-08-bond-calculator`）：活动被动只加自己，常见 +20% / +50%；全队光环用自定义百分比补。

## 3. 线 A：从者 extraPassive

### 3.1 字段

技能顶层没有时间窗。时间在嵌套数组 `skill.extraPassive[0]`：

| 字段 | 含义 |
| --- | --- |
| `eventId` | 所属活动 |
| `startedAt` / `endedAt` | 这条被动何时有效 |
| `condQuestId` / `condQuestPhase` | 解锁条件（清过某关），不是「只在该关生效」 |
| `functions[].funcType` | 羁绊条为 `servantFriendshipUp` |
| `funcTargetType` | `self` 自己；`ptFull` 全队含替补 |
| `svals[0].EventId` | 和活动绑定 |
| `svals[0].RateCount` | 千分比：200=+20%，500=+50%，50=+5%，1000=+100% |

时间窗三种形态：

1. 当前限时：窗口等于活动期（幕末 `1790229600–1792043999` = 北京 2026-09-24 14:00 ～ 2026-10-15 13:59）
2. 过期限时：`startedAt = endedAt = 2145888000`（关掉），或留下已经结束的历史窗口
3. 常驻主线：`endedAt = 2145888000` 且带 `condQuestId`。例：阿尔托莉雅「女杰的威风」`EventId 80059` 雅戈泰，文案是「该主线剧情通关时 +100%」

`event.svts` 是活动临时加入（幕末只有原田左之助），不是加成名单。加成只能从从者 `extraPassive` 反查。

### 3.3 另一种 extraPassive：活动礼装技能（99xxxx）

技能搜索「牵绊获得量提升」还会撞上礼装技能，不是从者被动：

- 自己 +100% / 满破 +200%，文案「在『某某活动』关卡…（作为助战时无效）」

## 4. 线 B：questCampaign + questFriendship

### 4.1 字段

| 字段 | 含义 |
| --- | --- |
| `event.type` | `questCampaign` |
| `startedAt` / `endedAt` | 活动日历 |
| `campaigns[].target` | 羁绊从者加成为 `questFriendship` |
| `campaigns[].value` | 千分倍率：`1200` = ×1.2（+20%），`1300` = ×1.3（+30%） |
| `campaigns[].calcType` | `multiplication` |
| `campaigns[].targetIds` | 从者 id；空 = 该范围关卡上全员都加 |
| `campaignQuests[].questId` | `0` = 期间几乎全关卡；非 0 = 只这些关 |
| `campaignQuests[].isExcepted` | `true` = 从全关卡里抠掉该关 |

接口：

- `https://api.atlasacademy.io/nice/CN/event/{id}`
- 活动目录：`https://api.atlasacademy.io/export/CN/basic_event.json`

## 5. 和计算器的缺口

| 场景 | 现在 | 线 A 按文案 | 线 B 按字段 |
| --- | --- | --- | --- |
| 手选幕末近藤勇，打活动关 | 可能叠进过期 extraPassive | 只加当前有效的 +50% | 若同时有 questFriendship 再加 |
| 手选近藤勇，打冠位研钻 | 同上错误求和 | 活动被动文案指向活动关，默认 0 | 仅当存在 `questId=0` 的 questFriendship 且近藤在名单里 |
| 推荐/求解 | 全员 0 | 活动关应带上当前 extraPassive | 全关卡活动应带上名单从者 +20%/+30% |
| 玛修全队 +5% | 手选丢弃 | 需求：自定义 % 补；或单独做全队光环 | 线 B 的加成是「名单从者自己」，不是全队光环 |
| 种火本全员 +20% | 未接 | — | `targetIds` 空 + 限定 questId |
| 过期活动 | 手选会叠加 | 时间窗外丢弃 | 活动 endedAt 之后丢弃 |

快照目前只拉从者/礼装/关卡目录，没有 extraPassive，也没有 event campaign。页面启动约定不拉 Atlas 整包；线 A 现在是手选时单拉 `nice/servant/{id}`。

## 6. 拉取入口（给后续实现用）

线 A：

- 单从者：`GET https://api.atlasacademy.io/nice/CN/servant/{svtId}`（日服用 `JP`）
- 过滤：`functions.funcType == servantFriendshipUp`，跳过 `970663`
- 是否当前有效：`extraPassive[0].startedAt <= now <= extraPassive[0].endedAt`，且 `endedAt` 不要当成「主线常驻就全图鉴生效」
- 是否当前关：`svals.EventId` 对上正在打的活动/主线；技能 `detail` 写明活动关或主线关

线 B：

- 目录：`GET https://api.atlasacademy.io/export/CN/basic_event.json`
- 详情：`GET https://api.atlasacademy.io/nice/CN/event/{id}`
- 过滤：`type == questCampaign` 且 `campaigns.target == questFriendship` 且日历未过期
- 从者：`targetIds`；空 = 范围内全员
- 关卡：`campaignQuests`；`questId==0` 且 `isExcepted==false` 为全关卡，再减去 `isExcepted==true` 的关

日更 cron 现为 UTC `17 16 * * *`（北京次日 00:17），快照成功会重写 `src/data/version.json` 的 `updatedAt`。

## 7. 还没定的点

1. 线 A 的限时自身加成，打冠位研钻算不算。玛修文案写死活动关；EX/A 只写「关卡通关时」+ 活动限定。
2. 主线 +100%（女杰的威风等）要不要在对应主线关计入；冠位研钻不计。
3. 线 A 全图鉴 extraPassive 是快照进目录，还是运行时按从者再拉。
4. 线 B 是快照一份「当前 questFriendship 名单」，还是打开页面时拉 `basic_event`。
5. 全队光环（玛修 +5%、活动礼装玛修 +20%）继续用手填自定义 %，还是自动加到全队第二层。
6. UI 档位：线 A 有 +30%、+100%；线 B 有 +20%、+30%。现下拉只有关 / +20% / +50%。

定这几条之后再改拉取和计算。
